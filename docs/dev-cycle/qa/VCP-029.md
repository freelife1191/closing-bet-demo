## 검사 대상에 관한 전제

`[VCP-028]` 은 바깥 `except` 가 이력을 지우던 것을 고쳤다. 이번에는 같은 함수 안쪽의 두 갈래를 고친다.
(가) 시그널이 있을 때 기존 로그와 병합하다 실패하면 오늘 자 행만 쓰던 것을, (나) 시그널이 없을 때
오늘 자 행을 걷어내다 실패하면 빈 파일을 쓰던 것을, 둘 다 파일을 그대로 두고 `False` 를 돌려주도록
바꿨다. (나)는 종전처럼 오늘 자 빈 최신 payload 를 쓴다.

두 갈래는 기존 CSV 를 `pd.read_csv` 로 읽지 못할 때 들어간다. 재현은 원본 사본 끝에 열 수가 다른
행 하나(26개 필드, 원본은 21열)를 덧붙여 `ParserError` 를 내게 한다. 원본 `data/` 는 읽기만 한다. 스크립트는
저장소의 `scripts.init_data` 와 `engine.screener` 를 import 하므로 `[INFRA-078]` 이 기록한 절대 경로 쓰기가
원본 `data/` 에 미칠 수 있어, 스크립트 끝에서 원본 `data/` 최상위 파일의 크기·mtime 을 앞뒤로 비교해
그 결과를 그대로 적는다. 보증 범위는 `signals_log.csv` 의 md5 와 그 스냅샷 비교다.

## 시나리오

### S-1. 병합 실패 갈래(가)는 파일을 보존하고 실패를 돌려준다 (회귀)
- 조작: 손상 사본을 두고 시그널 1건을 돌려주는 스크리너로 `create_signals_log(target_date="2026-09-22", run_ai=False)` 를 부른다.
- 기대: 반환값 `False`. 사본의 md5 가 실행 전과 같다(오늘 자 한 줄로 덮어쓰이지 않는다).
- 필수 여부(required): 예
- 실제: `S-1 result=False md5_same=True -> 통과`. 로그에는 「기존 로그 병합 실패: Error tokenizing data. C error:
  Expected 21 fields in line 17, saw 26 … <사본 경로>/data/signals_log.csv 를 보존하고 오늘 자 결과를 저장하지
  않습니다. 파일을 고친 뒤 다시 실행하십시오.」 가 찍혔다. pandas 예외 문구 끝의 줄바꿈 때문에 파일 경로가
  다음 줄에 이어진다.
- 결과: 통과

### S-3. 온전한 파일의 정상 병합은 종전대로 과거 행을 남기고 오늘 자 행을 붙인다 (인접)

### S-4. 「Refresh Data」 파이프라인의 단계 래퍼는 이 실패를 error 상태로 옮긴다 (진입 흐름)
- 조작: 손상 사본을 두고 `services.common_update_pipeline_steps._run_update_step` 에
  `step_name="VCP Signals"`, `execute_fn=create_signals_log(...)`, 상태를 기록하는 `update_item_status`,
  `STOP_REQUESTED=False` 인 shared_state 를 넣어 부른다. `run_vcp_signals_step` 자체는 안의
  `SignalTracker()` 가 저장소 `data/` 를 직접 열므로 부르지 않는다.
- 기대: 반환값 `None`. 상태 기록이 `[("VCP Signals", "running"), ("VCP Signals", "error")]` 이다. 사본의
  md5 가 같다. 화면의 VCP Signals 항목은 이 상태값을 그대로 보이므로 done 이 아니라 error 로 표시된다.
- 필수 여부(required): 예
- 실제: `S-4 result=None statuses=[('VCP Signals', 'running'), ('VCP Signals', 'error')] md5_same=True -> 통과`.
  래퍼의 로그 「VCP Signals Failed: step returned False」 가 ERROR 로 찍혔다.
- 결과: 통과
