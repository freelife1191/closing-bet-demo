## 검사 대상에 관한 전제

`create_signals_log` 는 성공(정상 저장·정상 0건 정리)에 True, 스크리너 예외·병합 실패·정리 실패에 False 를 돌려주고 DataFrame 을
돌려주는 갈래가 없다. 파이프라인은 False 면 예외를 던져 기존 except 갈래가 `status="error"` 와 「실패: 시그널 저장 실패. …」 를
세우게 하고 가격 동기화를 건너뛴다. True 면 방금 쓴 `vcp_signals_latest.json` 의 시그널 수로 「완료: N개 시그널 감지」 또는
「완료: 조건 충족 종목 없음」 을 낸다. 화면은 종전 코드대로 `status === 'error'` 를 「❌ 오류: {message}」 로, `success` 를
「✅ 업데이트 완료!」 로 보인다. 「Refresh VCP」 버튼은 모두에게 보이고 클릭 핸들러가 비관리자를 권한 모달로 막으며(`page.tsx`
1431행), 서버의 `require_admin` 이 신원 없는 요청을 403 으로 거부한다.

## 시나리오

### S-1. 저장 실패가 화면에 오류로 보인다 (회귀)
- 조작: `QA_VCP_MODE=fail` 로 띄운 격리 백엔드에서 관리자 세션으로 `localhost:57821/dashboard/kr/vcp` 를 열고 「Refresh VCP」 를
  누른 뒤 상태 문구를 읽는다. 같은 시점에 `GET /api/kr/signals/status` 도 직접 조회한다.
- 기대: 화면에 「❌ 오류: 실패: 시그널 저장 실패. logs/backend.log 의 WARNING 을 확인하십시오」, API `status: "error"`,
  `running: false`, 「조건 충족 종목 없음」 없음. 콘솔 오류 0건.
- 필수 여부(required): 예
- 실제: 관리자 세션 확인 `refreshButton: true` · `userLabel: "QA Admin"` · `/api/admin/check → 200`. 클릭 6초 뒤
  `errorLine: "❌ 오류: 실패: 시그널 저장 실패. logs/backend.log 의 WARNING 을 확인하십시오"` · `hasNoMatch: false` ·
  `hasSuccess: false` · 표 20행 유지. API `{'status': 'error', 'message': '실패: 시그널 저장 실패. logs/backend.log 의

## 이월한 발견

- 사본 `vcp_status.json` 의 옛 상태가 기동 직후 상태 API 에 그대로 보였다(「실패 4건 중 4건 재분석 완료」, running false).
  화면은 running 이 아니면 그 문구를 쓰지 않으므로 사용자에게는 드러나지 않는다. 기존 동작이라 기록만 남긴다.
- 화면 문구 「❌ 오류: 실패: …」 의 접두 중복은 except 갈래의 「실패: 」 와 화면의 「❌ 오류: 」 가 겹친 기존 형식이다(리뷰 낮은
  확신도 관찰). 이번 범위 밖이라 그대로 두었다.
