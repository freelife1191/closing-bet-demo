## 시나리오

### S-1. 겹친 두 실행이 저장한 행이 모두 남는다 (하네스, 필수)
- 조작: 실행 A(종목 목록 앞 절반, 수집 지연 4초)를 띄우고 1초 뒤 실행 B(뒤 절반, 지연 0초)를 띄운다. B 가 먼저 저장하고 A 가 나중에 저장한다
- 기대: 수정 뒤 2026-09-22 행이 A·B 합집합이고 09-21 이전 행이 그대로다. 수정 전 사본은 A 가 시작 때 읽은 값으로 덮어 B 의 행이 사라진다
- 실제: 종목 목록 1,997개를 A 998·B 999 로 나눴다. 두 커밋 모두 B 가 0.6초에 먼저 끝나고 A 가 4.6초에 나중에 저장했고 둘 다 `result=True`. 수정 뒤 09-22 행 1,997(합집합), 09-21 이전 234,816, 전체 236,813행. 수정 전 사본은 09-22 행 998(A 만, B 의 999행 유실), 전체 235,814행. 통과

### S-2. 저장 중 강제 종료되어도 기존 파일이 온전하다 (하네스, 필수)
- 조작: 전 종목으로 한 번 실행하고, 저장이 시작된 순간(수정 뒤: 임시 파일 `daily_prices.csv.*` 생성, 수정 전: 원본 파일 크기·수정 시각 변화)에 `SIGKILL` 한다
- 기대: 수정 뒤 `daily_prices.csv` 가 실행 전과 바이트 단위로 같다. 수정 전 사본은 파일이 잘린다
- 실제: 수정 뒤 두 번 실행했다. 임시 파일이 생긴 순간(0바이트) 종료한 경우와 임시 파일에 11,717,976바이트까지 쓰인 순간 종료한 경우 모두 반환 코드 -9, 원본이 11,898,792바이트로 실행 전 사본과 `filecmp` 동일, 243,462행으로 읽힘. 수정 전 사본은 원본 파일 변화를 감지한 순간 종료했고 파일이 0바이트로 잘려 `EmptyDataError`. 통과
- 부수 관찰: 수정 뒤에는 `SIGKILL` 로 끊긴 임시 파일 `daily_prices.csv.XXXXXXXX` 가 남는다. `.gitignore` 의 `data/*.csv` 에 걸리지 않는 것은 `signals_log.csv` 와 같은 기존 상태이며 `[INFRA-092]` 에 기록했다(`/review` L2)
