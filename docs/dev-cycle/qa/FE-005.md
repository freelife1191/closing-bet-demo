# [FE-005] HTTP 호출 경로를 `fetchAPI` 로 통일하고 세션 조회 중복을 없앤다 — QA 시나리오

- 대상 화면: http://localhost:3500/dashboard/kr, `/dashboard/kr/vcp`,
  `/dashboard/kr/closing-bet`, `/chatbot`
- 구성 근거: /qa-only 리포트 (`.gstack/qa-reports/qa-report-localhost-3500-2026-09-04.md`)
  + 이번 사이클의 변경 열 파일
- 구성 2026-09-04 09:58 | 실행 (미실행)

이 항목은 결함을 고치는 사이클이 아니라 호출 경로를 옮기는 사이클입니다. 그래서 회귀
시나리오가 검사하는 것은 「고친 것이 고쳐졌는가」가 아니라 「옮긴 것이 그대로 동작하는가」
입니다. 이관한 여덟 호출 가운데 브라우저에서 무해하게 실행할 수 있는 다섯을 시나리오로
삼았습니다.

나머지 셋은 시나리오에 넣지 않았습니다. `updateMarketGate` 는 3.7MB 짜리
`data/all_institutional_trend_data.csv` 와 Market Gate JSON 을 덮어쓰고,
`reanalyzeVCPFailedAI` 와 `runVCPScreener` 는 LLM 요금을 발생시킵니다.
`archive-format.md` §8 이 비용이 드는 조작을 시나리오에서 제외하도록 규정합니다. 세 함수의
요청 형태와 `timeout` 값은 `frontend/src/lib/api.test.ts` 의 단위 검사가 고정합니다.

## 시나리오

### S-1. 세션 ID 는 한 번만 발급되고 화면을 옮겨도 유지된다 (회귀)
- 조작: `/dashboard/kr` 를 연 뒤 `localStorage` 의 키 목록과 `browser_session_id` 값을
  읽는다. `/dashboard/kr/vcp` → `/dashboard/kr/closing-bet` → `/chatbot` 순으로 옮기며
  같은 값을 다시 읽는다.
- 기대: 키 목록에 세션 ID 로 쓰이는 항목은 `browser_session_id` 하나뿐이고
  (`nextauth.message` 와 `chatbot_current_model` 은 용도가 다름), 값이 `anon_` 으로
  시작하며 네 화면에서 완전히 같다.
- 결과:

### S-2. 사용량 표시가 세션 ID 로 조회해 값을 그린다 (회귀)
- 조작: 네 화면 각각에서 사이드바 하단의 사용량 문구를 읽고, 같은 시점의 네트워크에서
  `/api/kr/user/quota` 요청의 질의 문자열을 확인한다.
- 기대: 문구가 「무료 사용량 10회 남음」이고, 요청이
  `?email=&session_id=anon_…` 형태로 나가 200 을 받는다. `session_id` 값이 S-1 에서 읽은
  `localStorage` 값과 문자 하나까지 같다.
- 결과:

### S-3. 모의투자 모달의 세 조회가 값을 그린다 (회귀)
- 조작: 사이드바의 「모의투자」를 눌러 모달을 연다. 「거래 내역」 탭을 누른다.
- 기대: 모달을 열 때 `GET /api/portfolio` 와
  `GET /api/portfolio/history/asset?days=365` 가 각각 200 을 받고, 헤더에 총 평가 자산과
  예수금이 원 단위 숫자로 표시된다. 「거래 내역」 탭에서
  `GET /api/portfolio/history?limit=50` 이 200 을 받고 표에 일시·종목명·유형·체결가·수량·
  총액 열을 갖춘 행이 하나 이상 그려진다.
- 결과:

### S-4. 수익 차트의 기간 필터가 `days` 인자를 전달한다 (회귀)
- 조작: 모의투자 모달의 「수익 차트」 탭을 누른 뒤 기간 버튼 「3개월」을 누른다.
- 기대: `GET /api/portfolio/history/asset?days=90` 이 나가 200 을 받는다. 모달을 열 때
  나갔던 `days=365` 와 다른 요청이다.
- 결과:

### S-5. VCP 상태 폴링이 캐시를 우회한다 (회귀)
- 조작: `/dashboard/kr/vcp` 를 열고 10초 이상 머문 뒤 네트워크에서
  `/api/kr/signals/status` 요청을 모두 확인한다.
- 기대: 요청이 두 번 이상 나가고 각각 서로 다른 `?_t=` 값을 갖는다. 모두 200 이며 브라우저
  캐시에서 응답한 것이 아니다. 이 호출에 `cache: 'no-store'` 를 붙였으므로 같은 URL 이
  반복되어도 서버까지 닿아야 한다.
- 결과:

### S-6. 네 화면이 콘솔 오류 없이 그려진다 (인접)
- 조작: 네 화면을 차례로 열고 각각에서 콘솔 오류를 확인한다. 모의투자 모달의 탭 넷을
  눌러 본 뒤에도 다시 확인한다.
- 기대: 네 화면 모두 콘솔 오류 0건이다. 특히 `Hydration failed` 나 `Text content did not
  match` 같은 Next.js 하이드레이션 오류가 없고, 모듈을 찾지 못하는 오류도 없다. 세션 ID
  발급 코드가 새 파일 `frontend/src/lib/session.ts` 로 옮겨 갔으므로 이 화면들이 그 파일을
  제대로 불러오는지가 여기서 드러난다.
- 결과:

### S-7. 챗봇 화면의 대화 목록과 모델 선택이 채워진다 (인접)
- 조작: `/chatbot` 을 연다.
- 기대: `GET /api/kr/chatbot/models` 와 `GET /api/kr/chatbot/sessions` 가 각각 200 을
  받는다. 왼쪽 「최근 대화」 절에 「저장된 대화가 없습니다.」가 표시되고, 입력창 왼쪽 모델
  선택 항목에 「FLASH」가 표시된다. 이 화면의 `getAuthHeaders` 에서 세션 ID 발급 사본을
  제거했으므로 헤더가 비어 요청이 막히지 않는지가 여기서 드러난다.
- 결과:

### S-8. 관측한 요청 가운데 실패 응답이 없다 (인접)
- 조작: S-1 부터 S-7 까지를 마친 시점에 네트워크 기록 전체에서 4xx 와 5xx 응답을 센다.
- 기대: 0건이다. `fetchAPI` 가 이제 실패 응답 본문의 사유를 예외로 올리므로, 이관한

## 이월한 발견

1단계 리포트가 네 건을 지적했고 모두 이번 항목의 범위 밖입니다. 이번 항목이 고치기로 한
것은 HTTP 호출 경로와 세션 ID 발급 중복이며, 네 건은 모두 접근성·표기·요청 횟수 문제라
성격이 다릅니다. 그리고 네 건 모두 이미 백로그에 항목이 있어 새로 만들지 않았습니다.

- ISSUE-001 「Refresh Market Gate Only 버튼에 접근 가능한 이름이 없다」 → `[FE-031]`.
  이번 사이클의 code-reviewer 지적으로 만든 항목에 이미 체크박스로 들어가 있습니다.
- ISSUE-002 「브레드크럼 홈 링크에 접근 가능한 이름이 없다」 → `[FE-029]`. 그 항목이
  `Header.tsx:23` 의 `<a href="/">` 를 이미 지목하고 있습니다. 오늘 실측이 그 진단을
  뒷받침합니다.
- ISSUE-003 「비로그인 방문자에게 특정 이름으로 인사한다」 → `[FE-022]`. **다만 그
  항목의 진단 방향이 오늘 실측과 반대여서 바로잡았습니다.** 그 항목은 「챗봇 화면은 실제
  계정 이름을 알고 있는데 사이드바만 자리표시자」라고 적고 있었으나, 오늘
  `/api/auth/session` 을 조회한 결과 `user` 자체가 없었습니다. 사용량 조회의 `email=` 도
  비어 있습니다. 즉 로그인하지 않은 상태이므로 사이드바의 「User」가 맞고 챗봇의
  「흑기사님」이 자리표시자입니다. 이 방향을 바로잡지 않으면 다음 사이클이 사이드바를
  챗봇에 맞추는 잘못된 방향으로 고칩니다.
- ISSUE-004 「사용량 조회가 화면 하나에 여러 번 나간다」 → `[FE-021]` 에 확인 대상으로
  덧붙였습니다. 그 항목이 누적 성과 화면의 같은 성질을 이미 다루고 있고, 개발 모드
  StrictMode 의 이중 실행인지를 프로덕션 빌드에서 먼저 확인하도록 규정합니다. 화면만
  다른 같은 현상이므로 새 항목을 만들지 않았습니다.
