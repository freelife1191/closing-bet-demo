## 시나리오

### S-1. 취소하면 처리하지 않은 행의 기존 AI 값이 남는다 (핵심)
- 조작: CSV 세 행(기존 값 `HOLD/50/prev`)에 Gemini 강제 재분석을 실행하고, 첫 종목을 처리한 뒤 취소한다.
- 기대: 검증 사본에서는 첫 행만 `BUY`, 나머지 두 행은 `HOLD/50/prev` 이고 응답은 `cancelled`, `updated 1 / still_failed 0` 이다. 기준 사본에서는 두 행이 `분석 실패` 로 덮여 결함이 재현된다.
- 필수 여부(required): 예
- 실제: 검증 `status=cancelled updated=1 still_failed=0 rows=['000001:BUY/80/ok', '000002:HOLD/50/prev', '000003:HOLD/50/prev']`. 기준 `updated=1 still_failed=2 rows=['000001:BUY/80.0/ok', '000002:nan/nan/분석 실패', '000003:nan/nan/분석 실패']` 로 결함이 재현되었다. 검증 쪽 신뢰도가 `80` 으로 적힌 것은 열에 결측이 생기지 않아 정수형이 유지된 결과다
- 결과: 통과

### S-2. 처리했지만 실패한 행은 실패로 기록한다 (경계)
- 조작: 두 번째 종목이 예외를 내게 하고, 두 종목을 처리한 뒤 취소한다.
- 기대: 두 사본 모두 두 번째 행은 `분석 실패` 다. 검증 사본에서 세 번째 행은 기존 값이며 집계는 `1 / 1` 이다.
- 필수 여부(required): 예
- 실제: 검증 `updated=1 still_failed=1 rows=['000001:BUY/80.0/ok', '000002:nan/nan/분석 실패', '000003:HOLD/50.0/prev']`. 기준은 세 번째 행까지 `분석 실패` 이고 `still_failed=2` 다
- 결과: 통과

- 기대: 검증 사본에서 세 행 모두 기존 값이며 집계는 `0 / 0`, 오류가 없다.
- 필수 여부(required): 예
