## 검사에 쓰는 세션 (실측 자료)

`data/chatbot_storage.db` 에 실제로 들어 있는 세션이며 읽기 전용으로 확인했습니다.

| 이름 | 세션 ID | 소유자 | 메시지 |
|---|---|---|---|
| 남의 anon 세션 | `95cb5b28-5267-40ec-b3ac-2aee56b4630d` | `anon_5423673b-4e48-47f3-906e-9b4e55abfc5e` | 10건 |
| 레거시 세션 | `171cbdd2-db51-4b42-b5a6-3702a24d0dc4` | NULL | 7건 |
| VCP 세션 | `vcp_000660_213d479a-3f2c-44a6-94b4-172b6fa4bfd7` | `admin@hodu.dev` | 4건 |

소유자는 요청 헤더로 정해집니다. `X-User-Email` 이 있고 `user@example.com` 이 아니면 그
이메일이고, 아니면 `X-Session-Id` 헤더의 값입니다. 화면은 `localStorage` 의
`browser_session_id` 를 언제나 `X-Session-Id` 로 싣습니다.

## 하지 않는 조작

- **챗봇에 메시지를 보내지 않습니다.** 실제 Gemini 호출과 쿼터 소모가 일어납니다
- **`/clear all` 을 입력창에 보내지 않습니다.** 요청자 자신의 대화만 지우게 되었지만
  여전히 되돌릴 수 없습니다. 명령어 목록의 문구만 읽습니다
- **대화 삭제 버튼과 메시지 삭제 버튼을 누르지 않습니다.** 확인 모달이 떠도 「취소」만
  누릅니다. 사이드바 항목은 접근 가능한 이름이 없어 삭제 버튼과 구분되지 않으므로
  (`ISSUE-002`) 대화를 열 때는 제목 텍스트 요소를 눌러야 합니다
- **서버에 `DELETE` 요청을 보내지 않습니다.** 삭제 경로의 검사는 pytest 15건이 맡습니다
- VCP 화면의 「실패 AI 재분석」·「Refresh VCP」·「VCP 전체 10주 매수」를 누르지 않습니다

## 이월한 발견

`/qa-only` 리포트가 지적한 세 가지는 모두 이번 변경이 만든 것이 아니라 그 자리에 원래
있던 것입니다. 셋 다 이번 항목의 범위를 넘으므로 백로그로 올립니다.

- ISSUE-001 「슬래시 명령 자동완성이 하단 빠른 조회 버튼에 가려진다」와
  ISSUE-003 「같은 `/clear` 명령의 설명이 화면마다 다르다」 → `[CHAT-019]` 로 묶어
  올렸습니다. 둘 다 같은 자동완성 UI 의 문제이므로 따로 세우면 한 자리를 두 번 건드립니다
- ISSUE-002 「사이드바 대화 항목과 삭제 버튼의 접근 가능한 이름이 비어 있다」 → 백로그의
  `[CHAT-007]` 「사이드바 대화 항목을 키보드로 열 수 있게 만든다」가 같은 자리를 다루므로
  그 항목에 합쳤습니다. 대화 제목을 접근 가능한 이름으로 노출하는 것과 삭제 버튼에
  `aria-label` 을 붙이는 것을 체크박스로 더했습니다
