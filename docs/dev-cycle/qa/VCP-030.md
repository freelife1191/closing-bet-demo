## 시나리오

### S-1. 0바이트 로그에서 회복하고, 원자적으로 한 번 쓴다 (핵심)
- 조작: 사본의 `data/signals_log.csv` 를 0바이트로 만든다. 가짜 스크리너와 쓰기 계측을 건 상태에서 `create_signals_log(target_date="2026-09-23", run_ai=False)` 를 부른다
- 기대
  - 반환값이 True 다
  - `signals_log.csv` 쓰기는 `atomic` 1회이고 `to_csv` 로 직접 쓴 것은 0회다
  - 파일이 BOM 으로 시작하고 「QA종목030」 한 행을 담는다
  - 대조군(변경 전 커밋)은 같은 조작에서 False 를 돌려주고 파일이 0바이트로 남는다
- 필수 여부(required): 예
- 실제: 반환 `True`. 경고 「… 가 비어 있어 기존 로그 없이 이어갑니다」 1건. 쓰기 `[('atomic', …/code/data/signals_log.csv)]` 1건, `to_csv` 0건. 크기 0 → 258, BOM 있음, 임시 파일 없음, `rows=1`, `[{'ticker': '999030', 'name': 'QA종목030', 'signal_date': '2026-09-23'}]`. 대조군은 반환 `False`, 「기존 로그 병합 실패: No columns to parse from file」, 쓰기 0건, 크기 0 그대로
- 결과: 통과

### S-2. 쓰기 도중 실패해도 기존 로그가 잘리지 않는다 (계획 검토 R1)
- 조작: 원본에서 복사한 로그가 있는 상태에서 `os.fsync` 를 실패시킨다. 이 상태로 시그널이 있는 경우(병합 갈래)와 없는 경우(당일 정리 갈래)를 각각 실행한다
- 기대: 두 경우 모두 반환값이 False 이고, 로그 파일의 SHA-256 이 실행 전과 같다. `signals_log.csv.*` 임시 파일은 남지 않는다
- 필수 여부(required): 예
- 실제: 병합 갈래는 반환 `False`, 「기존 로그 병합 실패: QA forced fsync failure」, 쓰기 시도 `atomic` 1건, 크기 1727 → 1727, `same_bytes=True`, 임시 파일 없음, 15행 그대로. 당일 정리 갈래는 반환 `False`, 「기존 VCP 로그 정리 실패: QA forced fsync failure」, 같은 결과. 대조군은 `to_csv` 가 fsync 를 부르지 않아 두 갈래 모두 `True` 로 끝나 이 주입으로 실패를 만들 수 없었다(병합 갈래는 16행으로 덮어씀). 대조군은 비원자 쓰기의 존재를 보이는 용도다
- 결과: 통과
