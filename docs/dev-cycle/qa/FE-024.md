## 전제

이 화면을 여는 브라우저 세션은 **관리자가 아닙니다.** `useAdmin` 훅이
`/api/admin/check?email=` 로 판정하는데 이 계정은 `ADMIN_EMAILS` 에 없습니다. 그래서 비용을
일으키는 조작이 두 겹으로 막힙니다.

- 카드별 「이 종목만 재분석」 버튼은 **렌더 자체가 되지 않습니다.**
- 「스크리너 전체 업데이트」와 「GEMINI AI 재분석」은 눌러도 이번 사이클이 만든 확인 모달이
  아니라 「권한 없음」 모달이 뜹니다.

따라서 확인 모달의 문구와 취소·실행 분기는 브라우저로 검사할 수 없습니다. 그 부분은
`frontend/src/app/dashboard/kr/closing-bet/page.regression-fe-024.test.tsx` 가 `useAdmin`
을 관리자로 목킹해 여덟 건으로 고정합니다. 브라우저가 맡는 것은 **이름이 실제로 붙었는지**와
**비용 요청이 나가지 않는지** 두 가지입니다.

## 시나리오

### S-1. 화면의 모든 버튼이 접근 가능한 이름을 가진다 (회귀)
- 조작: 화면을 연 뒤 모든 `button` 요소를 훑어 보이는 문구와 `aria-label` 가운데 하나라도
  비어 있지 않은지 센다. `title` 속성은 이름으로 치지 않는다.
- 기대: 버튼 **21개**, 그 가운데 이름이 없는 것 **0개**.
- 결과: 통과. 안정 상태에서 버튼 **21개**, 이름 없는 것 **0개**. 화면을 연 직후 잠깐
  22개가 되는데 늘어난 하나는 안내 배너의 「안내 문구 닫기」이며 그 버튼도 이름을 갖고
  있어 이름 없는 버튼은 두 상태 모두 0개다. 총수 21은 절대값이 아니라 안정 상태의 값이다.

### S-2. 헤더의 아이콘 버튼 셋이 무엇을 하는지 말한다 (회귀)
- 조작: 헤더의 햄버거·돋보기·종 모양 버튼의 접근 가능한 이름을 읽는다. 앞의 둘은
  `lg` 미만 폭에서만 보이므로 뷰포트를 375x812 로 좁혀서 확인한다.
- 기대: 차례로 「메뉴 열고 닫기」, 「검색」, 「설정 열기」. 종 모양은 알림이 아니라 사이드바의
  설정 창을 열므로 「알림」이 아니라 「설정 열기」여야 한다.
- 결과: 통과. 375x812 에서 셋 다 실제로 보이고, 이름은 차례로 「메뉴 열고 닫기」,
  「검색」, 「설정 열기」다. 종 모양 버튼이 「알림」으로 읽히지 않는다.

### S-3. 챗봇 토글의 이름은 고정이고 상태는 `aria-expanded` 가 말한다 (회귀)
- 조작: 오른쪽 아래 챗봇 버튼의 이름과 `aria-expanded` 를 읽는다. 한 번 눌러 열고 다시
  읽는다. 한 번 더 눌러 닫고 다시 읽는다.
- 기대: 이름은 세 번 모두 「AI 상담」으로 같고, `aria-expanded` 만 `false` → `true` →
  `false` 로 바뀐다. 이름이 「열기」와 「닫기」로 바뀌면 안 된다. 상태를 이름에 실으면
  스크린 리더가 버튼을 다른 버튼으로 읽는다.
- 결과: 통과. 이름은 세 번 모두 「AI 상담」으로 같고 `aria-expanded` 만 `false` →
  `true` → `false` 로 바뀐다.

### S-4. 챗봇을 열어도 이름 없는 버튼이 생기지 않는다 (회귀)
- 조작: 챗봇 패널을 연 상태에서 다시 모든 버튼을 훑는다.
- 기대: 버튼 **28개**로 늘고, 이름이 없는 것은 여전히 **0개**.
- 결과: 통과. 버튼 **28개**로 늘고 이름 없는 것은 **0개**. 늘어난 여덟은 「새 대화 시작」,
  「AI 상담 닫기」, 추천 질문 넷, 「보내기」, 그리고 패널 안의 토글이다.

### S-5. 비용을 일으키는 두 버튼이 요청을 내보내지 않는다 (회귀)
- 조작: DATA STATUS 절의 「스크리너 전체 업데이트」와 「GEMINI AI 재분석」을 차례로 누른다.
  뜨는 모달의 제목과 본문을 읽고 닫는다. 네트워크 기록에서 `/api/kr/jongga-v2/run` 과
  `/api/kr/jongga-v2/reanalyze-gemini` 로 나간 요청을 센다.
- 기대: 두 버튼 모두 「권한 없음 / 관리자만 실행할 수 있습니다」 모달이 뜨고, 두 엔드포인트로
  나간 요청은 **0건**. 모달의 버튼은 「닫기」와 「확인」 둘 다 이름이 있다.
- **이 시나리오에서 「실행」 버튼을 누르지 않는다.** 관리자 세션이었다면 그 버튼이 실제
  지출을 일으킨다.
- 결과: 통과. 두 버튼 모두 「권한 없음 / 관리자만 실행할 수 있습니다」 모달이 뜨고, 모달의
  버튼은 「닫기」와 「확인」으로 둘 다 이름이 있다. 두 엔드포인트로 나간 요청은 **0건**.
  「실행」 버튼은 누르지 않았고, 비관리자 세션이라 확인 모달까지 가지도 않았다.
  이 0건이 기록 기능의 침묵이 아님을 대조군으로 확인했다. 비용이 들지 않는 「선택한 날짜의
  리포트 다시 불러오기」를 누르니 `GET /api/kr/jongga-v2/latest → 200` 이 기록에 잡혔다.
  버튼을 고를 때 좌표나 색인이 아니라 `aria-label` 로 지목할 수 있었던 것이 이번 항목의
  성과다. 이름이 없던 때에는 `fa-sync-alt` 아이콘 버튼이 둘이라 색인으로 고르면 비용
  버튼을 누를 위험이 있었다.

### S-6. 상세 모달을 열어도 이름 없는 버튼이 생기지 않는다 (회귀)
- 조작: 첫 카드의 「상세 분석 보기」를 눌러 종목 상세 모달을 연다. 모달이 뜬 뒤 모든 버튼을
  훑는다.
- 기대: 버튼이 **22개**로 늘고 이름 없는 것은 **0개**. 늘어난 하나는 모달의 닫기 버튼이며
  이름은 「닫기」다.
- 결과: 통과. 버튼이 **22개**로 늘고 이름 없는 것은 **0개**. 늘어난 하나는 「닫기」다.

### S-7. 상세 모달이 Escape 로 닫힌다 (인접)
- 조작: S-6 에서 연 모달에서 Escape 를 누른다.
- 기대: 모달이 닫히고 버튼 수가 **21개**로 돌아온다. 이름이 「닫기」인 버튼이 사라진다.
- 결과: 통과. Escape 로 닫히고 버튼 수가 **21개**로 돌아왔다. 이름이 「닫기」인 버튼이
  사라진 것을 따로 셈해 확인했다(0개).

### S-8. 필터를 걸어 카드 수가 달라져도 이름 없는 버튼이 생기지 않는다 (인접)
- 조작: 등급 선택 상자를 「S급 이상」으로 바꾸고, 이어서 「전체」로 되돌린다. 각 상태에서
  버튼을 훑는다.
- 기대: 카드 수가 달라져 버튼 총수는 바뀌지만 이름 없는 버튼은 두 상태 모두 **0개**.
  카드마다 붙는 「상세 분석 보기」와 「모의 매수」가 카드 수에 따라 늘고 주는 것이 정상이다.
- 결과: 통과. 「S급 이상」에서는 해당 종목이 없어 카드가 0개가 되고, 카드마다 붙던 버튼
  여섯이 사라지는 대신 「필터 초기화」 하나가 생겨 총 **16개**가 된다. 「전체」로 되돌리면
  카드 3개와 함께 **21개**로 복귀한다. 두 상태 모두 이름 없는 것은 **0개**.

### S-9. 전 과정에서 콘솔 오류가 없다 (인접)
- 조작: S-1 부터 S-8 까지를 마친 뒤 콘솔의 오류 기록을 읽는다.
- 기대: 오류 **0건**. 이번 사이클은 `aria-label` 과 상태 변수 하나를 더했을 뿐이므로 새
  오류가 날 자리가 없다.
- 결과: 통과. 오류 **0건**. 콘솔 기록 전체에서 `error` 문자열이 잡힌 줄도 0줄이다.
