## 검사 대상에 관한 전제

이번 변경은 예외 갈래 하나를 바꾼다. 종전에는 그 갈래가 열 13개짜리 빈 DataFrame 을
`data/signals_log.csv` 에 그대로 써서, 스크리너 생성이나 모델 초기화처럼 try 안 어디서든
예외가 나면 그날까지 쌓인 모든 날짜의 행이 사라졌다. 고친 뒤에는 파일이 있으면 손대지 않고,
없을 때만 정상 갈래(「VCP 조건 충족 종목 없음」)와 같은 23개 열의 빈 파일을 만든다.

예외를 실환경에서 일으키려면 스케줄러의 17시 실행을 기다리거나 「Refresh VCP」 를 눌러야
하는데, 후자는 되돌릴 수 없는 조작이고 `data/` 는 읽기 전용이다. 그래서 원본 CSV 의 사본을
scratchpad 디렉터리에 두고 `init_data.BASE_DIR` 을 그 디렉터리로 바꾼 뒤, 스크리너 클래스만
생성자에서 예외를 내는 더미로 바꾸어 함수를 불렀다. 회귀 테스트가 `run_screening` 에서
예외를 내는 것과 달리 여기서는 생성자에서 내므로, 예외 지점이 달라도 같은 갈래로 떨어지는
것을 함께 확인한다. 화면 코드와 원본 자료에는 손대지 않았다.

## 시나리오

### S-1. 이력이 있는 파일은 예외 뒤에도 그대로다 (회귀)
- 조작: 원본 15행 사본을 둔 상태에서 스크리너 생성자가 `RuntimeError` 를 내게 하고
  `create_signals_log(target_date="2026-09-22", run_ai=False)` 를 부른다.
- 기대: 반환값 `False`. 파일의 md5 와 행 수(15)가 실행 전과 같다.
- 필수 여부(required): 예
- 실제: `S-1 result=False rows 15->15 md5_same=True -> 통과`. 로그에는
  「VCP 분석 실패: QA: screener init failure」 와 「VCP 분석 오류 - 기존 로그 보존, 빈 최신 결과
  저장」 이 찍혔다.
- 결과: 통과
- 증거: 스크립트 출력 원문(위 「실제」)
- 정리(cleanup): 사본 디렉터리 삭제

### S-2. 파일이 없으면 정상 갈래와 같은 23개 열의 빈 파일을 만든다 (회귀)
- 조작: 사본 파일을 지우고 S-1 과 같은 예외로 다시 부른다.
- 기대: 반환값 `False`. 0행이고 열이 23개이며 `is_vcp`·`hold_days` 가 들어 있다.
  `vcp_signals_latest.json` 은 오늘 날짜에 시그널 0건으로 쓰인다(종전과 같은 동작).
- 필수 여부(required): 예
- 실제: `S-2 result=False rows=0 cols=23 -> 통과`, `latest payload date=2026-09-22 signals=0`.
- 결과: 통과
- 증거: 스크립트 출력 원문(위 「실제」)
- 정리(cleanup): 사본 디렉터리 삭제

### S-3. 정상 「없음」 갈래는 종전대로 오늘 자 행만 지우고 나머지를 남긴다 (인접)
- 조작: 원본 사본에 `signal_date` 를 2026-09-22 로 바꾼 행 2개를 덧붙여 17행으로 만들고,
  빈 DataFrame 을 돌려주는 스크리너로 같은 함수를 부른다. 열 목록을 모듈 상수로 뽑은 변경이
  이 갈래의 동작을 바꾸지 않았는지 본다.
- 기대: 반환값 `True`. 15행이 남고 2026-09-22 행은 없다.
- 필수 여부(required): 아니오 (인접)
- 실제: `S-3 result=True rows 17->15 today_rows_left=False -> 통과`.
- 결과: 통과
- 증거: 스크립트 출력 원문(위 「실제」)
- 정리(cleanup): 사본 디렉터리 삭제
