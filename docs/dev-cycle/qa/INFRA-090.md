## 리뷰에서 기록만 한 사항

- 심층 리뷰 M1: 관리자 수동 갱신의 stale 검증(`services/common_update_pipeline_steps.py:61-90`)은 원본 CSV 의 최대 날짜를 읽는다. `get_last_trading_date` 가 지수 조회 실패로 휴장일을 기대 날짜로 돌려주면, 수정 뒤에는 휴장일 행이 없어 그 단계가 stale 로 실패한다. 수정 전에는 0원 행 덕분에 통과했다. 기대 날짜가 휴장일이 되는 것 자체가 `[INFRA-089]`(지수 조회 실패)의 증상이므로 그 항목에 이월한다
- 심층 리뷰 L1: 휴장 기간의 실행은 파일을 다시 쓰지 않으므로, 이미 저장된 0원 행은 연휴가 끝난 뒤 첫 저장 때까지 남아 VCP·종가베팅이 읽는다. 승인한 「저장 시 자동 정리」의 잔여 영향이다. 운영자 확인 항목에 적었다
- 심층 리뷰 L4: 실제 거래일에 KRX 가 아직 확정하지 않아 전 종목 종가 0 을 주면 그날은 저장하지 않고 성공으로 끝난다. 다음 실행에서 다시 조회되어 복구된다. KRX 가 장 마감 뒤 그런 응답을 주는지는 확인하지 못했다
- 코드 리뷰 low: 종가가 전부 숫자가 아닌 날짜도 0 으로 본다(계획 Global Constraints). 휴장일 응답에 종가 0 이 아닌 행이 섞이면 종전처럼 저장한다(실측 휴장일은 모두 전 종목 0)
