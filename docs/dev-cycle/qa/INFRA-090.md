## 시나리오

### S-1. 실제 휴장일 조회가 0원 행을 저장하지 않고 폴백하지 않는다 (핵심, KRX 로그인 필요)
- 조작: 사본 `daily_prices.csv` 를 09-23 까지로 자른 뒤(09-23 행 수를 기록), 사본에서 원본 `.env` 의 `KRX_ID`·`KRX_PW` 만 프로세스 환경으로 넘겨 `create_daily_prices(target_date="2026-09-24")` 를 한 번 실행한다. `fetch_prices_yfinance` 호출 수를 센다
- 기대: 반환 `True`, 로그 「2026-09-24 전 종목 종가 0, 저장 생략」과 「모두 휴장일」, 폴백 0회, 파일에 09-24 행 없음, 09-23 행 수·종가 합계가 실행 전과 같음
- 조건: 같은 계정 로그인이 운영 세션에 영향을 줄 수 있어(`[INFRA-089]`) 실행 전 사용자 승인이 필요하다

### S-2. 로컬 원본의 설 연휴 0원 행이 다음 저장 때 빠진다 (네트워크 없음)
- 조작: 사본의 원본 복사본(02-16·17·18 각 2,882종목 종가 0)을 그대로 두고, pykrx 만 가짜로 바꿔(파일 마지막 날짜 다음 평일에 정상 프레임 2종목) `create_daily_prices` 를 한 번 실행한다
- 기대: 반환 `True`, WARNING 「전 종목 종가 0 인 저장 날짜 ['2026-02-16', '2026-02-17', '2026-02-18'] 를 제외」, 저장 뒤 세 날짜 0행, 나머지 날짜의 행 수는 실행 전과 같고 새 날짜 2행이 늘어남, 종가 0 비율 100% 인 날짜 0개

### S-3. 종목 차트에 휴장일 0원 봉이 나오지 않는다 (브라우저)
- 조작: 사본에서 `SCHEDULER_ENABLED=false` 로 gunicorn 과 Next 를 대체 포트로 띄운다. S-2 실행 전과 후에 브라우저로 Next 주소의 `/api/kr/stock-chart/005930?period=1m&end=2026-02-28` 을 열어 응답의 날짜와 종가를 기록하고 스크린샷을 남긴다
- 기대: S-2 전에는 02-16~18 이 종가 0 으로 들어 있고, S-2 뒤에는 그 세 날짜가 없으며 종가 0 인 봉이 0개다

## 리뷰에서 기록만 한 사항

- 심층 리뷰 M1: 관리자 수동 갱신의 stale 검증(`services/common_update_pipeline_steps.py:61-90`)은 원본 CSV 의 최대 날짜를 읽는다. `get_last_trading_date` 가 지수 조회 실패로 휴장일을 기대 날짜로 돌려주면, 수정 뒤에는 휴장일 행이 없어 그 단계가 stale 로 실패한다. 수정 전에는 0원 행 덕분에 통과했다. 기대 날짜가 휴장일이 되는 것 자체가 `[INFRA-089]`(지수 조회 실패)의 증상이므로 그 항목에 이월한다
- 심층 리뷰 L1: 휴장 기간의 실행은 파일을 다시 쓰지 않으므로, 이미 저장된 0원 행은 연휴가 끝난 뒤 첫 저장 때까지 남아 VCP·종가베팅이 읽는다. 승인한 「저장 시 자동 정리」의 잔여 영향이다. 운영자 확인 항목에 적었다
- 심층 리뷰 L4: 실제 거래일에 KRX 가 아직 확정하지 않아 전 종목 종가 0 을 주면 그날은 저장하지 않고 성공으로 끝난다. 다음 실행에서 다시 조회되어 복구된다. KRX 가 장 마감 뒤 그런 응답을 주는지는 확인하지 못했다
- 코드 리뷰 low: 종가가 전부 숫자가 아닌 날짜도 0 으로 본다(계획 Global Constraints). 휴장일 응답에 종가 0 이 아닌 행이 섞이면 종전처럼 저장한다(실측 휴장일은 모두 전 종목 0)
