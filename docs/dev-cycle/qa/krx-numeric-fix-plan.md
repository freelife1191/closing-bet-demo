# INFRA-072 / JONGGA-038 implementation plan

Goal: KRX 실응답의 종목코드를 보존하고 잘못된 캐시를 재조회한다. AI 숫자 재서술로 발생한 금액/가격 모순을 차단한다.
Architecture: 기존 collector/캐시 경계 및 jongga 전용 LLM 응답 경계만 수정. 새 의존성/프론트엔드/인증변경 없음.
승인: 사용자 '진행해', 직전 검증에서 확인한 두 TODO 수정과 실제 분석 재검증. 기존 자동승인 위임에 따라 진행.
Tier: T3, generator 데이터/LLM 경계. 설계는 기존 흐름의 bounded 변경이며 위험 경로 검토를 위해 계획 기록.

- [x] KRX 인덱스를 rename_axis('ticker')로 표준화, 빈/유효하지 않은 코드 변환은 오류. memory/SQLite malformed cache는 miss.
- [x] 명명/무명 인덱스, 잘못된캐시→재조회, 실패저장보존 RED/GREEN.
- [x] 모델의 reason은 숫자 없는 정성 분석으로 제한한다. 숫자/화폐 단위가 들어간 응답은 재생성1회 후 실패를 상위로 전파해 저장을 막는다. 숫자 기반 score/confidence는 기존 JSON필드로 유지.
- [x] 검증한 reason 뒤에 현재가·거래대금·수급을 입력으로부터 코드가 붙인다. 거래대금은 조/억과 원값으로 결정적 표현. 손절/목표는 기존 PositionSizer와 UI의 계산값을 유일한 기준으로 사용해 중복 계산하지 않는다.
- [x] 누락/중복 종목·불완전 응답도 종가 분석 성공으로 저장하지 않는다. VCP 등 일반 LLM 경로는 유지.
- [x] 독립 plan→Ponytail→code/architect→T3 deep 리뷰, 격리 전체pytest/Vitest 및 브라우저 QA.
- [x] 실제 KRX계정으로 전체분석(알림없음), 원자료·새 설명·화면검증. 기존 리포트백업, 오류면 보존.

Tradeoff: 모델이 절대 숫자로 제안하던 임의 손절/목표를 제거하고 시스템 계산값으로 안내한다. 종목이름/제품세대 숫자도 reason에서는 피하도록 요청한다. 기존 성공 아닌 수치응답은 그대로 승인하지 않는다. 과거 리포트 원본은 보존하고 최신은 검증된 재분석 결과로 갱신한다. 모든 자연어 의미 정확성을 보장한다고 주장하지 않는다.

Safety: .env 값 노출/변경 금지. 3500/5501 서비스 조작·실제API는root만, 알림/거래금지. 원본rootpackage 보존. 테스트는복제scratch/가짜전송, 실제재분석만비용허용.
