## 시나리오

### S-1. 로그인 사용자의 계정 삭제가 세 저장소에서 그 이메일의 행을 지운다 (회귀)
- 조작: 세션 쿠키로 /chatbot 을 열어 「삭제 검사」 한 건을 보내고, 설정 모달에서 이름·직무를 저장하고,
  모의투자 화면에서 종목 하나를 1주 매수한다. 사본 `data/chatbot_storage.db`·`data/paper_trading.db`·
  `data/user_quota.json` 에 그 이메일 행·키가 생겼는지 읽는다. 설정 모달 프로필 탭의 「계정 삭제」 → 「삭제
  (복구 불가)」 를 누른다.
- 기대: 화면이 `/` 로 이동하고 로그인 상태가 풀린다. 네트워크에 `DELETE /api/kr/user/data` 200 과 응답
  `{"status":"deleted","deleted":{"chat_sessions":1,"chat_memories":true,"paper_trading":true,"usage":true}}`.
  사본 `chatbot_storage.db` 의 `chatbot_sessions`·`chatbot_messages`(세션 경유)·`chatbot_memories` 에 그 이메일
  행 0, `user_quota.json` 에 그 이메일 키와 `recharge_day:` 키 없음. `paper_trading.db` 는 `portfolio`·`trade_log`
  행 0 이고 `balance` 는 없거나 초기 잔고 `100000000`, `asset_history` 는 없거나 삭제 시각 이후 항목만. 뒤의 두
  조건이 느슨한 이유는 `GET /api/portfolio` 가 `get_balance` 로 잔고 행을 다시 만들고 자산 이력을 기록하기
  때문이다(`CLAUDE.md` Important Notes 4, `common_portfolio_routes.py:93`). 로그아웃이 끝나기 전 대시보드 폴링
  한 번이면 두 행이 되살아난다. 콘솔 오류 0(삭제 전 `console --clear`).
