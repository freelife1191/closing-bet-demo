# [INFRA-025] QA 시나리오와 결과

- 항목: `/api/system/env` 가 인증 없이 서버 `.env` 를 읽고 쓴다
- 티어: T3 | 계획 작성: 2026-09-07 | 계획 도구: `/qa-only`
- 검증 기준 커밋: (첫 커밋에서 채운다) | 실행: | 실행 도구: `/qa`
- 브라우저: Aside 를 쓸 수 없어(`NEEDS_ASIDE`) gstack 내장 브라우저
  `~/.claude/skills/gstack/browse/dist/browse` 로 실행한다. macOS 이므로 Aside 안내는
  이 줄로 갈음한다.

## 사전 조건

**워커가 새 코드를 들고 있어야 한다.** 이 저장소의 gunicorn 은 `--reload` 없이 뜨므로
파이썬을 고친 뒤 재기동하지 않으면 옛 코드가 그대로 응답한다. 2026-09-05 에 남긴
`gunicorn-needs-hup-before-qa` 학습이 그것이고, 이번 라운드에서 그 확인을 건너뛴 탓에
아래 「사고 기록」의 자료 손실이 났다.

    실행 전 확인: ps -o pid,lstart -p $(pgrep -f "gunicorn.*flask_app" | head -1)
    기준: 워커 기동 시각 > 마지막 소스 수정 시각
    현재: 워커 2026-09-07 16:41:12 기동. 소스 최종 수정 16:4x. 조건 충족.

**`.env` 를 건드리지 않는다.** 아래 시나리오의 POST 는 전부 「허용 목록 밖 키만 담은
요청」이거나 「빈 본문」이다. `update_env_file` 은 필터링 후 남는 키가 없으면 파일을 열지
않고 돌아가므로 파일이 바뀌지 않는다. 시나리오 전후로 SHA-256 을 대조해 그것을 증명한다.

    기준 해시: a199feaf799bfe8dad4ef3ab6cc296aee5f7dd961787fa1a7d81d84d06410f6d

**토큰은 화면에 출력하지 않는다.** `curl` 에 넘길 때 셸 변수로만 다루고
`TOKEN=$(grep '^ADMIN_API_TOKEN=' .env | cut -d= -f2-)` 형태로 읽는다. 응답 본문을 볼 때도
`ADMIN_API_TOKEN` 은 허용 목록에 없어 애초에 실리지 않는다.

## 기대값

**게이트 (Flask 직접, `http://127.0.0.1:5501`)**

| 요청 | 기대 |
|---|---|
| `GET /api/system/env` (헤더 없음) | 403, 본문 `{"error":"Forbidden"}` |
| `GET` + `X-Admin-Token: wrong` | 403 |
| `GET` + `X-Admin-Token: 토큰` (비ASCII) | 403 — 500 이면 실패 |
| `GET` + 올바른 토큰 | 200 |
| `POST` (헤더 없음) | 403 |
| `DELETE` + 올바른 토큰 | 라우트에 없음. 405 가 정답이나 현재 앱은 500 을 돌려준다(`[INFRA-017]`) |

**응답 내용 (올바른 토큰, `GET`)**

| 확인 | 기대 |
|---|---|
| 반환 키 개수 | 10 (허용 목록 12개 중 `.env` 에 값이 있는 것) |
| `ADMIN_EMAILS` 포함 | 아니오 |
| `ADMIN_API_TOKEN` 포함 | 아니오 |
| `GOOGLE_APPLICATION_CREDENTIALS` 포함 | 아니오 |
| `SMTP_PORT` | 평문 |
| `SMTP_HOST` | 평문 |
| 나머지 8개 | 전부 `*` 포함 |
| `SMTP_PASSWORD` | 전부 `*` (24자 이하이므로 앞뒤를 남기지 않는다) |

변경 전에는 이 요청이 인증 없이 45개 키를 돌려주었고 그 안에 `ADMIN_EMAILS` 가 평문으로
있었다. 45 → 10 과 관리자 이메일의 소거가 이번 라운드의 핵심 증거다.

**우회 경로 (Next 경유, `http://127.0.0.1:3500`)**

| 요청 | 기대 |
|---|---|
| `GET /api/system/env` (세션 없음) | 403 — 라우트 핸들러가 막는다 |
| `GET /api/system%2Fenv` (`--path-as-is`, 세션 없음) | 403 — rewrite 를 타고 Flask 에 닿지만 토큰 검사에 걸린다 |

두 번째 줄이 이번 설계의 근거다. rewrite 제외만 믿었다면 이 경로로 `.env` 가 그대로
나갔다. 계획 검토와 보안 리뷰가 각각 지적했고 보안 리뷰가 실측으로 확인했다.

**화면 (비로그인 = 비관리자)**

| 확인 | 기대 |
|---|---|
| 사이드바에서 설정 모달을 연다 | 열린다 |
| 「일반」 탭 | 보인다 |
| 「API & 기능」·「알림 센터」·「시스템」 탭 | 보이지 않는다 |
| 「설정」 그룹 라벨 | 보이지 않는다 |
| 네트워크에 `/api/system/env` 요청 | 없다 |

관리자 화면은 NextAuth 구글 세션이 필요하고 내장 브라우저에는 그 세션이 없다. 관리자
경로는 `frontend/src/app/api/system/env/route.test.ts` 4건과
`SettingsModal.admin-gate.test.tsx` 의 관리자 케이스가 고정하며, 이 문서의 실행 결과에
그 사실을 적는다.

10번은 `.env` 를 쓰지 않는 경로임을 앞에서 논증했고, 그럼에도 전후 해시를 대조해
실증한다. 해시가 달라지면 그 자체가 실패다.

13번을 선택으로 두는 이유는 현재 앱이 405 대신 500 을 돌려주기 때문이다. 원인은
`app/__init__.py:254` 의 전역 예외 처리기이며 `[INFRA-017]` 의 범위다. 이번 라운드는
「`DELETE` 로 `.env` 가 초기화되지 않는다」까지만 보장한다.

## 하지 않는 것

- 설정 모달의 「저장」을 누르지 않는다. `AGENTS.md` 가 되돌릴 수 없는 조작으로 지정했다.
- 알림 테스트 발송을 하지 않는다. 실제 메시지가 나간다.
- 챗봇 전송, 재분석, Refresh, 모의투자를 누르지 않는다.
- `data/` 를 쓰지 않는다.
- 관리자 계정으로 로그인하지 않는다. 자격 증명을 다루지 않는다.

## 사고 기록 — 이 라운드에서 자료가 지워졌다

QA 와 직접 관련은 없으나 같은 날 같은 경로에서 벌어진 일이므로 여기에 남긴다.

보안 리뷰 에이전트가 실측을 하던 시각에 백엔드는 15:01 에 기동한 옛 코드였고
`DELETE /api/system/env` 가 열려 있었다. 그 요청이 실제로 실행되어 `.env` 의 자격 증명
11개가 비워지고 `data/` 의 파일 7개가 지워졌다. `.env` 는 `.env.bak.20260901_084454` 에서
11개 전부 되살렸고, 되돌리기 전 상태는 `.env.bak.20260907_164102` 에 남겼다.
`data/chatbot_storage.db` 와 `data/chatbot_sessions.json` 은 백업이 없어 잃었다.

원인은 두 가지다. 첫째, 서브에이전트에게 「읽기 전용」이라고만 지시하고 실행 중인 서버에
요청을 보내지 말라는 제약과 그 경로가 파괴적이라는 사실을 전달하지 않았다. 둘째,
`gunicorn-needs-hup-before-qa` 학습이 있었는데도 리뷰 전에 워커 기동 시각을 확인하지
않았다. 재발 방지는 `AGENTS.md` 의 「되돌릴 수 없는 조작」 절에 적었다.
