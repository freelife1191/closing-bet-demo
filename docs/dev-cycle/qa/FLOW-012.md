## 이번 변경이 화면에 닿는 경로

`services/kr_market_stock_detail_service.py:232` 가 `verify_with_references=True` 로
수급 서비스를 부르며, 그 결과가 종목 상세 API 의 `investorTrend5Day` 로 실려 종가베팅
카드의 상세 모달에 「투자자 동향 (오늘 기준 5영업일)」로 그려집니다. 이번 변경이 실제로
작동하는 경로가 곧 아래 시나리오가 검사하는 경로입니다.

**카드의 「외인 (5일)」은 이번 검사 대상이 아닙니다.** 그 값은 시그널 파일이 신호가 나온
거래일 기준으로 저장해 둔 것이라 수급 서비스를 거치지 않습니다. 같은 화면에 수급이 두
벌 있고 출처가 서로 다르므로, 시나리오는 모달 쪽만 봅니다. 두 값이 갈리는 것 자체는
S-4 에서 의도된 동작으로 확인합니다.

## 시나리오

- 기대: 아래 아홉 쌍과 모두 일치한다. 이 아홉 종목은 CSV 에 이상징후가 없어 참조 조회
  자체가 일어나지 않는 경로이므로, 이번 변경 전후로 값이 달라지지 않아야 한다.

### S-2. 정확한 CSV 가 참조 값으로 덮이지 않는다 (회귀)
- 조작: `curl -s http://localhost:5501/api/kr/stock-detail/108490` 과
  `.../096770` 을 불러 `data.investorTrend5Day` 를 읽는다.
- 기대: 로보티즈는 `foreign=84286017500`, `institution=35863006000` 이고,
  SK이노베이션은 `foreign=82645477900`, `institution=162488708300` 이다. 두 종목 모두
  CSV 원본값과 완전히 같다. 이상징후가 없으면 참조를 부르지 않으므로 CSV 가 그대로
  살아남는 것이 이번 변경이 지키려는 성질이다.
- 결과: 통과. 두 종목 모두 API 가 CSV 원본값을 그대로 돌려주었다.

### S-3. 이상징후가 붙은 종목만 참조 값으로 교체된다 (회귀)
- 조작: `curl -s http://localhost:5501/api/kr/stock-detail/<코드>` 를 세 종목
  (022100 포스코DX, 047050 포스코인터내셔널, 316140 우리금융지주)에 대해 부른다.
- 기대: 세 종목 모두 `investorTrend5Day` 가 아래 값으로 내려오며, 이는 CSV 원본이 아니라
  Toss 참조에서 온 값이다. 참조가 `_reference_reject_reason` 을 통과했다는 뜻이다.

  | 종목 | 채택된 외국인 | CSV 원본 외국인 | 채택된 기관 |
  |---|---|---|---|
  | 포스코DX (022100) | -75억 (-7,481,667,400) | -50억 | +1,959억 |
  | 포스코인터내셔널 (047050) | -351억 (-35,115,880,800) | -288억 | +9,798억 |
  | 우리금융지주 (316140) | +3,992억 (399,167,794,900) | +4,131억 | +718억 |
- 결과: 통과. 세 종목 모두 CSV 원본이 아닌 Toss 참조 값으로 내려왔다.

### S-4. 카드와 모달이 서로 다른 기준일을 쓴다 (회귀)
- 조작: 날짜 선택 상자를 2026-02-11 로 바꾼 뒤 LG전자(066570) 카드의 「외인 (5일)」과
  「기관 (5일)」을 읽고, 같은 카드의 상세 모달을 열어 「투자자 동향」의 외국인과 기관을
  읽는다.
- 기대: 카드는 `689억` 과 `326억` 이고 모달은 `-249억` 과 `-51억` 이다. 카드는 신호가
  나온 거래일 기준이고 모달은 늘 오늘 기준이므로 두 값이 다른 것이 정상이며, 두 섹션의
  툴팁이 각각 그 기준을 설명한다.
- 결과: 통과. 카드 `689억 / 326억`, 모달 `-249억 / -51억` 로 학습에 기록된 값과 같았다.

### S-5. 모달을 닫는 두 수단이 모두 동작한다 (인접)
- 조작: 로보티즈 카드의 모달을 열어 닫기 버튼(`aria-label="닫기"`)으로 닫고, 다시 열어
  Escape 키로 닫는다.
- 기대: 두 번 모두 모달이 사라지고 카드 목록으로 돌아오며, 콘솔에 오류가 남지 않는다.
- 결과: 통과. 닫기 버튼과 Escape 모두 모달을 없앴고 콘솔 오류는 0건이었다.

### S-6. 종목을 바꾸면 수급 값도 함께 바뀐다 (인접)
- 조작: 로보티즈 모달을 열어 값을 읽고 닫은 뒤, SK이노베이션 모달을 열어 값을 읽는다.
- 기대: 로보티즈는 `+843억 / +359억`, SK이노베이션은 `+826억 / +1625억` 로 서로 다르다.
  한 종목의 값이 캐시되어 다른 종목에 재사용되지 않는다.
- 결과: 통과. S-1 의 아홉 종목 순회에서 모든 값이 종목마다 달랐다.

### S-7. 등급 필터를 걸어도 모달의 수급 값이 같다 (인접)
- 조작: 등급 필터를 「A급 이상」으로 바꾸고 남은 카드의 상세 모달을 연다.
- 기대: 카드가 1건(로보티즈)으로 줄고, 그 종목의 모달 수급 값은 필터를 걸기 전과 같은
  `+843억 / +359억` 이다. 필터는 목록을 좁힐 뿐 수급 조회 경로를 바꾸지 않는다.
- **구성할 때 적었던 기대값을 실측에 맞춰 고쳤습니다.** `/qa-only` 리포트는 「S급 이상」에서
  카드가 1건으로 줄었다고 적었으나, 오늘 시그널 아홉 건의 등급은 A 1건과 B 8건이고 S 는
  없습니다. 「S급 이상」은 0건이 나오는 것이 옳고 실제로 0건과 `No Signals Found` 가
  나왔습니다. 리포트가 가리킨 1건은 「A급 이상」의 결과입니다.
- 결과: 통과. 「A급 이상」에서 로보티즈 1건이 남았고 모달 값은 `+843억 / +359억` 로 필터
  적용 전과 같았다. 필터를 「전체」로 되돌리면 9건으로 복구되었다.

### S-8. 좁은 화면에서도 수급 값이 온전히 보인다 (인접)
- 조작: 뷰포트를 375x812 로 바꾸고 로보티즈 모달을 연다.
- 기대: 모달 폭이 375 이내이고 가로 스크롤이 생기지 않으며, 외국인·기관·개인 세 값이
  데스크톱과 같은 `+843억 / +359억 / -1526억` 로 읽힌다.
- 결과: 통과. 모달 폭 375, `scrollWidth` 와 `clientWidth` 가 모두 375 로 가로 넘침이
  없었고 세 값이 데스크톱과 같았다.

## 이월한 발견

`/qa-only` 가 보고한 세 가지는 모두 종목 상세 모달의 다른 섹션에 있고 수급 서비스와
무관합니다. 이번 항목의 범위 밖이므로 고치지 않고 백로그로 넘깁니다.

- ISSUE-001 「EPS 와 순이익의 부호가 서로 어긋난다」 → `[JONGGA-033]`. Toss 응답의
  `indicators.eps` 와 `financials.net_income` 이 서로 다른 기간을 보는 것으로 보이며,
  어느 쪽을 기준으로 맞출지 정해야 해서 이번 범위를 넘는다.
- ISSUE-002 「종목 상세 모달에 dialog 역할과 포커스 이동이 없다」 → 기존 `[FE-030]` 에
  이미 같은 내용이 실측 근거와 함께 적혀 있다. 새 항목을 만들지 않는다.
- ISSUE-003 「PER 툴팁이 음수 PER 을 설명하지 못한다」 → `[FE-035]`. 툴팁 문구를 고치는
  일이라 수급 서비스와 접점이 없다.
