## 시나리오

### S-1. Toss 백필이 기존 행을 덮지 않고 빈 칸만 채운다 (하네스, 필수)
- 조작: 두 사본에서 `backfill` 모드로 실행. pykrx 는 빈 응답이고, 수집 도중 다른 실행이 (09-22, 005930) 정확값 `777000000/-888000000` 을 저장한다. Toss 는 두 종목 모두 09-22·09-21·09-18 에 수량 7·9, 종가 1000 을 준다
- 기대: 수정 전은 파일에 있던 005930 의 09-18·09-21·09-22 와 000660 의 09-21 이 근사값 `7000/9000` 으로 바뀐다. 수정 뒤는 이 넷이 원래 값(`111000000/-222000000`, `333000000/444000000`, `777000000/-888000000`, `-555000000/0`)을 유지하고, 파일에 없던 000660 의 09-18·09-22 만 `7000/9000` 으로 채워진다. 069500 행은 둘 다 그대로. 두 쪽 모두 `result=true`
- 실제: 22:01:16 실행, 두 사본 모두 exit 0·Traceback 0·`result=true`·9행. 수정 전(`0a7b84e`)은 9행 모두 `7000/9000` 이다. 파일에 있던 정확값 다섯 행(005930 09-18·09-21·09-22, 000660 09-21, 069500 09-21)이 전부 근사값으로 바뀌었다. 수정 뒤(`7ce711a`)는 그 다섯 행이 원래 값(`111000000/-222000000`, `333000000/444000000`, `777000000/-888000000`, `-555000000/0`, `1/2`)을 유지했고, 빈 칸이던 000660·069500 의 09-18·09-22 네 행만 `7000/9000` 으로 채워졌다. 기대와 다른 점은 069500 이다. 수집 대상에 069500 이 자동으로 더해지고 가짜 Toss 가 모든 종목에 상세를 주므로, 069500 도 000660 과 같은 모양이 되었다(수정 전 09-21 덮임, 수정 뒤 보존과 빈 칸 채움). 설계가 의도한 동작과 같으므로 통과
