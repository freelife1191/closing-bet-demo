# [JONGGA-017] 영문자가 든 종목코드가 조회 경로에 따라 다른 코드가 된다 — QA 시나리오

- 대상 화면: http://localhost:3500/dashboard/kr/closing-bet
- 구성 근거: `/qa-only` 리포트 (`.gstack/qa-reports/qa-report-closing-bet-2026-09-04.md`)
  + 이번 사이클의 변경 세 파일
- 구성 2026-09-04 22:05 | 실행 (미실행)

이번 사이클이 고친 것은 `app/routes/kr_market_signal_common.py` 의 `_normalize_ticker` 입니다.
그 함수가 숫자만 남기는 바람에 영문자가 든 국내 종목코드가 다른 종목의 코드로 바뀌었습니다.
아크릴 `0007C0` 이 `000070` 이 되고, 아로마티카 `0015N0` 이 `000150` 이 되며,
삼성에피스홀딩스 `0126Z0` 이 `001260` 이 됩니다. 세 값 모두 실재하는 다른 종목의 코드입니다.
이력 조회는 이 정규화를 거치지 않고 최신 조회만 거치므로, 최신 자료에 이런 종목이 들어오는
날 두 경로가 서로 다른 회사를 가리켰습니다.

기대값은 2026-09-04 브라우저 실측값입니다.

### S-1. 아크릴의 코드가 카드와 모달과 외부 링크에서 같다 (회귀)
- 조작: 날짜 선택 상자에서 `2026-02-11` 을 고른다. 「아크릴」 카드의 종목명 아래 코드를
  읽고, 그 카드의 「상세 분석 보기」를 눌러 모달 머리글의 코드를 읽는다. 모달을 Escape 로
  닫고 그 카드의 「N 네이버」와 「토스」 링크 주소를 읽는다.
- 기대: 네 자리 모두 `0007C0` 이다. 카드가 `0007C0`, 모달 머리글이 `아크릴 / 0007C0 /
  KOSDAQ`, 네이버가 `https://m.stock.naver.com/domestic/stock/0007C0/main`, 토스가
  `https://tossinvest.com/stocks/0007C0` 다. `000070` 은 어디에도 나타나지 않는다.

## 이월한 발견

`/qa-only` 리포트가 지적한 넷은 모두 `[JONGGA-017]` 의 범위 밖입니다. 이 항목이 고치기로 한
것은 종목코드 정규화이고, 넷은 표기와 기준일과 호출 횟수의 문제입니다. 셋은 이미 백로그에
있어 새로 올리지 않았습니다.

- ISSUE-001 「카드의 「종가」 타일이 날짜에 따라 다른 날의 종가를 가리킨다」 →
  `[JONGGA-031]` 로 새로 올렸습니다. 기존 `[JONGGA-023]` 은 툴팁 문구를 맞추는 항목이고
  이것은 같은 타일이 날짜에 따라 다른 필드를 그리는 동작 문제여서 별개입니다.
- ISSUE-002 「점수표의 매매 원칙(+9%/-5%)과 카드의 전략 포인트(+5%/-3%)가 어긋난다」 →
  이미 `[JONGGA-020]` 에 같은 사실이 적혀 있습니다. 새 항목을 만들지 않았습니다.
- ISSUE-003 「자료 없는 날짜의 빈 상태가 영어이고 안내가 사실과 다르다」 → 이미
  `[JONGGA-023]` 과 `[FE-025]` 가 담고 있습니다. `[FE-025]` 의 첫 체크박스가 「필터로 0장이
  된 것인지 자료가 없는 것인지 구분되게 안내 문구를 나눔」이어서 이번에 찾은 자료 없는
  날짜의 경우까지 포함합니다. 새 항목을 만들지 않았습니다.
- ISSUE-004 「화면 진입 시 `dates` 와 `latest` API 를 각각 두 번 호출한다」 → 백로그에
  올리지 않았습니다. 개발 모드의 React Strict Mode 가 효과를 두 번 실행시키는 동작일 수
  있어 결함인지 자체가 미확정입니다. 운영 빌드에서 같은 기록이 나오는지 확인한 뒤에
  판정할 사안입니다.
