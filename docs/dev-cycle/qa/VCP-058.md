## 시나리오

### S-1. 저장이 도중에 실패해도 기존 파일이 남는다 (하네스, 필수)
- 조작: 시그널 1건짜리 기존 최신 파일을 두고, 직렬화할 수 없는 값이 두 번째 시그널에 든 저장을 부른다
- 기대: 수정 뒤 예외 `TypeError`, 파일 바이트 불변, `_count_latest_signals` 1, 임시 파일 0. 수정 전은 파일이 잘려 읽는 쪽이 0 을 받는다(결함 재현). 저장 함수 하나의 보존이다. `create_signals_log` 전체에서는 바깥 except 갈래가 `[VCP-028]` 설계대로 빈 결과를 다시 쓰므로 「이전 결과가 계속 보인다」의 증거가 아니다(심층 리뷰 Minor 1)
- 실제: 수정 뒤 `TypeError`, 바이트 불변(96→96), `_count_latest_signals` 1, 임시 파일 0. 수정 전은 `TypeError` 뒤 파일이 220바이트의 잘린 JSON 으로 바뀌어 시그널 수 0(결함 재현). 통과

### S-2. 쓰는 동안 읽어도 빈 파일이나 잘린 JSON 을 보지 않는다 (하네스, 필수)
- 조작: 시그널 3,000건 파일을 150번 다시 쓰는 동안 다른 스레드가 두 읽는 함수를 계속 부른다
- 기대: 수정 뒤 시그널 수가 3,000 이 아닌 읽기 0, 날짜를 못 읽은 경우 0, 임시 파일 0. 수정 전은 잘못 읽은 횟수가 0 보다 크다(타이밍에 따라 달라지므로 수정 전 수치는 참고)
- 실제: 수정 뒤 읽기 543회 중 시그널 수 오류 0·날짜 오류 0, 임시 파일 0(같은 폴더에 SQLite 캐시 `runtime_cache.db` 가 생겼다. 캐시 무효화가 여는 파일로 원본 `data/` 에도 있으며 임시 파일이 아니다). 수정 전은 읽기 172회 중 시그널 수 오류 145·날짜 오류 146(결함 재현). 통과

### S-3. 정상 저장의 내용은 수정 전후가 같다 (하네스, 필수, 회귀)
- 조작: numpy 정수·실수·불리언, `date`, `None` 이 든 시그널을 저장하고 `generated_at` 을 뺀 내용과 두 읽는 함수의 결과를 비교한다
- 기대: 내용·시그널 수·날짜가 수정 전후 같다. 파일 권한은 수정 전 umask 기준, 수정 뒤 0600(설계에서 수용한 부수 효과)
- 실제: `generated_at` 을 뺀 내용이 수정 전후 같다(`score` 81.5, `volume` 1234567, `flag` true, `d` "2026-09-25", `foreign_1d` null), 시그널 수 1·날짜 2026-09-25 도 같다. 권한은 수정 전 0644, 수정 뒤 0600. 통과

### S-4. 분석 실패 갈래에서 최신 파일 저장까지 실패해도 `False` 를 돌려준다 (하네스, 필수)
- 조작: (a) 스크리너가 예외를 내고 최신 파일 자리가 디렉터리라 저장이 `OSError` 로 실패하게 한다. (b) 스크리너만 예외를 내고 저장은 정상이다
- 기대: (a) 수정 뒤 `False`, `signals_log.csv` 바이트 불변, 임시 파일 0. 수정 전은 예외가 함수 밖으로 나온다(결함 재현). (b) 수정 전후 모두 `False`, 최신 파일은 날짜 2026-09-25·시그널 `[]`, 로그 불변
