건너뛰므로 `data/.*` 도 함께 링크합니다. 검사 전후로 `git status data/` 가 비어 있음을

## 정리와 사고 기록

**검사 중 원본 `data/signals_log.csv` 를 한 번 훼손했다.** S-4 용 사본 디렉터리를 만들 때
`ln -sf` 로 링크를 건 자리에 pandas 로 썼고, 그 쓰기가 링크를 따라가 원본을 덮었다.
`is_vcp` 열이 전부 `True` 로, `signal_date` 열이 전부 `2026-09-07` 로 바뀌었고 BOM 과
`ticker` 열의 여섯 자리 zero-padding 이 사라졌다. 이 파일은 `.gitignore` 대상이라 Git 으로
되돌릴 수 없었다.

복구는 지난 라운드(`[JONGGA-008]`)가 scratchpad 에 남긴 QA 사본에서 형식을 되찾아 했다.
그 사본은 `ticker` 를 문자열로 읽어 여섯 자리를 보존하고 있었고, 훼손된 파일과 나머지
15 개 열이 완전히 일치하는 것을 대조해 확인했다. `signal_date` 가 15 행 전부 `2026-05-05`
라는 사실은 `qa-report-localhost-3500-2026-09-07-vcp-019.md:64` 가 기록해 두었다.
`is_vcp` 가 전부 비어 있었다는 것은 2026-09-01·09-02·09-07 의 리포트 네 건이 일치해서
말한다. 복구 뒤 백엔드를 재기동해 「오늘(2026-09-07) 기준 VCP 시그널이 없습니다. 최신
저장 데이터는 2026-05-05입니다」라는 훼손 전과 같은 응답을 얻어 확인했다.

두 번째 시도에서는 링크를 먼저 지우고 `cp` 로 실제 파일을 만든 뒤 편집했고, 편집 직전에
`os.path.islink` 로 확인하고 편집 전후의 원본 SHA-256 을 대조했다. 두 해시가 같았다.
