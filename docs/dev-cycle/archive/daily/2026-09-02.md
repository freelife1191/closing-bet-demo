- 메모: 감사가 지목한 세 증상, 즉 청크마다 fetchSessions() 를 부르는 것과 done 분기가
  실행되지 않는 것과 isCreatingSessionRef 가 남는 것이 모두 "SSE 루프가 렌더에 고정된
  클로저 값으로 세션을 비교한다" 는 한 원인에서 갈라져 나왔다. 그래서 그 한 곳만 고쳤다.

  첫 수정은 sessionIdRef 하나를 두고 effect 로 currentSessionId 와 동기화했다. 이것이
  회귀를 만들었다. 하나의 ref 에 서로 다른 두 상태, 즉 "화면에 표시된 세션" 과 "이 스트림이
  속한 세션" 을 함께 담았기 때문이다. 세션 A 가 스트리밍되는 동안 사용자가 B 를 클릭하면
  effect 가 ref 를 B 로 덮어쓰고, A 의 다음 청크가 sessionChanged 를 오판해 화면을 A 로
  되돌리며, isCreatingSessionRef 때문에 fetchHistory(A) 도 건너뛰어 세션 ID 와 메시지
  목록이 어긋난다. 코드 리뷰가 이것을 지적했다. ref 를 걷어내고 handleSend 안의 지역 변수
  streamSessionId 로 바꾸니 ref 선언과 effect 동기화가 함께 사라져 구현이 더 짧아졌다.

  회귀 테스트를 세 코드 버전에 각각 돌려 유효성을 확인했다. 원본에서는 1번과 2번이 실패하고
  3번이 통과하며, 첫 수정에서는 3번만 실패하고, 최종 구현에서 셋 다 통과한다. 3번 테스트는
  처음에 첫 수정에서도 통과했는데, 청크가 마이크로태스크만으로 연속 처리되어 React 가
  렌더를 배치하는 바람에 결함이 재현되지 않았기 때문이다. read() 안에 setTimeout 0 을 넣어
  실제 스트림처럼 태스크를 넘기게 하니 정확히 실패하게 되었다.

  jsdom 이 scrollIntoView 를 구현하지 않아 마운트 직후 자동 스크롤 effect 가 죽는다.
  beforeEach 에 Element.prototype.scrollIntoView 스텁을 넣어 막았다. 그리고 이 저장소의
  vitest.setup.ts 는 expect.extend 만 하고 타입 선언을 하지 않으므로 toBeInTheDocument 를
  쓰면 tsc 가 TS2339 를 낸다. 기존 테스트가 어디서도 쓰지 않는 것을 확인하고 toBeTruthy 로
  바꿨다.

  /qa-only 실측에서 이 사이클과 무관한 기존 결함 둘을 발견해 백로그에 넣었다. 대시보드
  진입 시의 하이드레이션 불일치가 [FE-008], 사이드바 대화 항목이 접근성 트리에 노출되지
  않는 문제가 [CHAT-007] 이다. 후자는 실측 도중 세션을 전환하려다 삭제 확인 모달이 뜨면서
  드러났다. 대화 항목이 onclick 을 붙인 div 라서 접근성 트리에는 같은 행의 삭제 버튼만
  button 으로 잡힌다.
