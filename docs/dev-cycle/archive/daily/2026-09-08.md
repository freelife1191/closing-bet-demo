## [INFRA-044] 인가 근거가 된 `ADMIN_EMAILS` 가 워커마다 갈릴 수 있다
- 완료 2026-09-08 00:30 | 티어 T1 | 커밋 b0ee535
- 변경: services/common_env_service.py, tests/app/test_common_env_service.py (+91 -1)
- 리뷰: ponytail-review(Lean already. Ship.) · security-reviewer(F1 실제 결함 발견,
  범위에 넣어 수정 · F2·F3 이월) · code-reviewer(개행 필터 판정 통과, 명령 치환 결함을
  새로 찾아 이월)
- 검증: pytest 1798 통과 · 2 skip · QA 시나리오 11/11 통과
- 메모: 항목이 적고 있던 전제 둘이 이미 거짓이었다. 「키 허용 목록이 없다」는
  `[INFRA-025]`(`95b022c`)가 이미 해소했고, 그 결과 「워커마다 갈린다」도 그 경로로는
  닫혀 있었다. 이 항목의 근거가 된 `[INFRA-037]` 사이클 보안 리뷰가 **바로 직전
  커밋인** 그 필터를 보지 못한 것이다. 리뷰가 지적한 파일을 열어 볼 때는 그 리뷰가
  어느 시점의 코드를 봤는지 먼저 확인한다.
- 메모: 그럼에도 항목의 결론은 옳았다. **인가 키를 덮어쓸 경로가 실제로 남아 있었다.**
  필터가 `data` 의 키만 검사하고 값은 그대로 `f"{key}={value}\n"` 으로 내보냈으므로,
  값에 개행을 넣으면 한 항목이 두 줄로 나뉘어 목록 밖의 키를 쓸 수 있었다. 기존 줄
  갱신 경로(137행)와 새 키 추가 경로(148행) 둘 다 뚫렸다. 내가 「값을 바꿀 경로가
  없다」고 판단한 것은 `os.environ` 대입만 세고 파일 쓰기의 내용을 보지 않은 탓이다.
- 메모: **막는 쪽만 세면 경로를 놓친다.** `grep` 으로 `os.environ[...] = ...` 를 훑어
  세 자리를 찾고 그중 하나가 걸러진다는 것까지 확인했지만, 그 함수가 파일에 무엇을
  어떻게 쓰는지는 읽지 않았다. 인가 근거를 다룰 때는 「누가 이 값을 바꾸는가」뿐 아니라
  「이 값이 어디에 어떤 형식으로 저장되고 누가 그것을 어떻게 해석하는가」까지 따라간다.
- 메모: `frontend/.env` 는 루트 `.env` 의 심볼릭 링크다(`restart_all.sh:17`). 그래서
  `route.ts:28` 의 `process.env.ADMIN_EMAILS` 와 Flask 의 `is_admin_email` 이 같은 파일을
  근거로 삼고, 이 주입은 두 게이트를 한꺼번에 오염시킨다. 보안 리뷰가 알려 주었다.
- 메모: 코드 리뷰가 **개행 없이도 성립하는 더 큰 결함**을 찾았다. `.env` 를 bash 가
  `source` 하므로 허용된 키의 값에 `$(...)` 를 넣으면 다음 기동에서 임의 명령이
  실행된다. 재현해 확인했다. 이번 변경이 만든 것이 아니고 근본 수정이 쓰기 인용과
  기동 스크립트 양쪽에 걸쳐 `[INFRA-049]`(P0) 로 이월했다. **개행을 막았다고 값이
  안전해진 것이 아니다.** 이 파일에 쓰는 값은 여전히 셸이 해석한다.
- 메모: 허용 목록 방식이 차단 목록보다 나은 이유가 이 사이클에서 드러났다. 키 이름의
  대소문자·공백·유니코드 변형을 보안 리뷰가 직접 실행해 확인했는데 전부 「거부」로
  떨어졌다. `[INFRA-025]` 이전의 「키 이름에 KEY·SECRET 이 있는지 보는」 방식이었다면
  변형마다 구멍이 났을 자리다.
- 메모: 설정 화면의 저장 버튼은 운영 `.env` 를 실제로 다시 쓰므로 QA 에서 누를 수 없다.
  `tier-rules.md` §1-1 의 「화면이 없는 경로는 안전한 하네스를 검사 대상으로 삼는다」에
  따라 `update_env_file` 을 임시 디렉터리에 대해 직접 불렀다. HTTP 계층은 `.env` 를
  건드리지 않는 403 거부 경로만 실제로 쳤다.
- 메모: 리뷰 회신이 두 건 모두 중간에서 잘렸다. `SendMessage` 로 이어 받았는데
  `infra044-security` 는 두 번 잘려 세 번에 나눠 받았다. 긴 표나 목록이 들어가는 리뷰는
  잘릴 것을 예상하고 처음부터 절을 나눠 요청하는 편이 낫다.
