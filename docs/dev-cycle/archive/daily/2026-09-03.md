  계산 규칙이 바뀌었는데 시그니처가 데이터 파일의 mtime 과 크기로만 만들어져 있어서,
  `data/runtime_cache.db` 에 살아남은 옛 결과가 계속 적중해 고친 계산이 화면에 닿지 않는
  상태였다. `_CUMULATIVE_CACHE_SCHEMA_VERSION` 을 2에서 3으로 올렸고,
  `kr_market_backtest_summary_cache.py` 는 시그니처에 버전 항목 자체가 없어 상수와
  항목을 새로 넣었다. 두 파일 모두 `tier-rules.md` §2 의 저장소 스키마 위험 경로에 있어
  티어를 T2 에서 T3 으로 올렸고, 그래서 `/review` 를 추가로 돌렸다.

  ponytail-review 는 5건을 지적했고 전부 반영해 구현 변경이 72줄에서 53줄로 줄었다.
  가장 큰 것은 `page.tsx` 에 새로 만든 `BacktestStatus` 유니언 타입 8줄이다. 런타임
  보증 없이 `as BacktestStatus` 캐스팅만 새로 만든다는 지적이었고, 테스트가 타입상
  불가능해야 할 `'OK'` 를 실제로 넣는다는 것이 그 증거였다. 상수와 함수로 나눈 것도
  호출 두 곳에는 과해서 함수 하나에 배열을 인라인했다. `determine_backtest_status` 의
  독스트링에서는 이 함수가 내지 않는 값까지 약속하던 둘째 문단 3줄을 지웠고,
  `verify_cumulative_data.py` 의 if/else 4줄은 지역 변수와 2줄로 줄였다. vitest 네
  블록의 반복은 `it.each` 표 하나로 묶었다.

  code-reviewer 는 확신도 80 이상 2건 외에 확인해 준 것들이 있다.
  `determine_backtest_status` 호출부는 두 곳이 전부이고, `profitFactor: None` 을 숫자로
  가정하는 소비자가 없으며 `jsonify` 와 `NumpyEncoder` 모두 `null` 로 통과시킨다는 점,
  그리고 새 vitest 네 케이스 가운데 셋이 옛 구현에서 실패한다는 판별력 확인이다.
  `test_jongga_stats_marks_open_only_window_as_pending` 하나는 옛 코드에서도 PENDING 이라
  판별력이 없지만 의도를 못 박는 용도로 남겼다.

  변이 검사는 여섯 갈래를 만들어 전부 검출을 확인했다. 승률 0 을 곧바로 PENDING 으로
  되돌리기, 손실 0 일 때 총이익을 손익비로 내보내기, VCP 임시 상태를 `"OK"` 로
  되돌리기, 확인 아이콘을 옛 `status === 'OK'` 비교로 되돌리기, 손익비 `null` 을 그대로
  그리기, 요약 캐시 시그니처에서 버전 항목 제거하기다. 다섯째 검사에서
  `run_mutation` 안의 `eval "$cmd"` 가 `cd frontend` 를 실행하는 바람에 작업 디렉터리가
  셸에 남아 다음 반복의 상대 경로가 깨졌다. 결과를 "검출" 로 잘못 읽었고 `page.tsx` 에
  변이가 복원되지 않은 채 남았다. `.bak` 로 되돌리고 절대 경로로 다시 돌려 정상 검출을
  확인했다.

  브라우저 실측은 gunicorn 마스터(PID 89674)를 `kill -HUP` 으로 재기동한 뒤에 했다.
  자동 리로드가 없어 재기동하지 않으면 옛 코드를 측정하게 된다. 확인 아이콘이 `15 trades`
  와 `180 trades` 두 곳에서 켜졌고(옛 코드는 0개), 백테스트 요약이 `vcp: BAD/15/33.3%`,
  `closing_bet: BAD/180/34.5%` 로 나왔으며, 누적 성과의 손익비 카드가 `1.09` 를 그렸다.
  캐시 무효화도 실증했다. 재기동 후 `backtest_summary_cache` 64행과
  `cumulative_performance_cache` 16행이 모두 새 시각으로 다시 기록되었고 행 수가 상한에
  맞아 프루닝도 정상 동작했다.

  손익비가 `null` 인 경로는 브라우저에서 관측하지 못했다. 저장 데이터 180건 가운데
  손실이 110건이라 `gross_loss` 가 0 이 되지 않는다. pytest 1건과 vitest 2건과 변이 1갈래로
  대신 덮었다.

  `toBeInTheDocument` 를 쓴 새 vitest 파일이 tsc 에서 세 곳 실패했고 그 여파로 smoke
  테스트 3건이 함께 실패했다. `frontend/vitest.setup.ts` 가 `expect.extend(matchers)` 만
  하고 타입 확장을 하지 않기 때문이다. 저장소 전체에서 이 매처를 쓰는 파일이 새로 만든
  것 하나뿐이었고 기존 관례가 `not.toBeNull()` 이어서 관례대로 바꿨다. 제 변경이 만든
  회귀가 아니라 제 테스트 파일이 만든 것이었다.
