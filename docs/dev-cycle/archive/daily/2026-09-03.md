- 메모: 세 결함 모두 값을 만들어 놓고 쓰지 않아 기능이 조용히 죽어 있던 자리다.

  첫째, 스트리밍 경로의 토큰 사용량이 늘 비어 있었다. `stream_single_model_response` 가
  청크에서 `text` 만 꺼내고 `usage_metadata` 를 보지 않아 `chat_handlers.py:186` 의
  `if usage_metadata:` 가 항상 거짓이 되었다. 함께 `extract_usage_metadata` 도 고쳤다.
  `hasattr` 만 검사해서 `usage_metadata=None` 인 응답에 값이 전부 0 인 딕셔너리를
  돌려주고 있었는데, 스트리밍 청크가 대부분 그 형태로 온다. 한 곳을 고쳐 스트리밍과
  비스트리밍 두 경로가 함께 나았다. `google-genai==1.62.0` 의 `total_token_count` 는
  "the entire request" 의 합계이므로 증분이 아니라 누적값이다. 그래서 마지막 유효값을
  남기도록 했다.

  둘째, `is_ephemeral_command` 가 바로 위에 선언된 `_EPHEMERAL_COMMANDS` 를 참조하지
  않고 `startswith("/")` 만 검사했다. `command_service.handle_command` 와 같은
  `split()` 으로 첫 토큰을 뽑아 집합과 대조하도록 고쳤다.

  셋째, 의도 지시문이 종가베팅 질문에만 실렸다. TODO 는 네 의도에도 실을지 네 의도의
  지시문 생성을 걷어낼지 정하라고만 적혀 있었는데, 싣는 쪽으로 정했다. 근거가 셋이다.
  네 의도의 지시문이 각각 의미 있는 내용을 담고 있어 걷어내면 기능이 줄고, 관심종목
  지시문까지 함께 버려지고 있었으며, 싣는 쪽이 코드도 짧아진다. 조건 하나와 파라미터
  하나가 사라지고 두 함수의 반환이 3튜플에서 2튜플로 줄었다.

  `_EPHEMERAL_COMMANDS`(`/status`, `/help`)와
  `storage_history_helpers.has_meaningful_user_message` 의 목록(`/status`, `/help`,
  `/memory view`, `/clear`)이 다른데, 서로 다른 질문에 답하므로 결함이 아니다. 앞의 것은
  저장할지를 정하고 뒤의 것은 세션 목록에 표시할지를 정한다. `/clear` 만 있는 세션은
  저장은 되되 목록에는 뜨지 않는다. qa-only 실측에서 이 맞물림이 설계대로 동작하는 것을
  확인했다. `/clear` 만 있던 세션이 목록에 없다가 실제 질문이 더해진 뒤 나타났다.

  `tests/test_chatbot_feature.py::test_slash_commands` 가 전체 pytest 에서 실패했다.
  모든 슬래시 명령이 임시라는 이전 동작을 못 박고 있었기 때문이며, 결함이 아니라 의도한
  동작 변경이다. 실제 값을 프로브로 확인한 뒤 새 사양을 못 박도록 갱신했다.

  지운 검사가 하나다. `tests/chatbot/test_session_access.py` 의 상태 변경 명령 판정만
  보던 검사이며, 새로 넣은 `tests/chatbot/test_core_command_mixin.py` 가 같은 판정을
  부른 뒤 저장 결과까지 확인해 포함 관계였다. 같은 파일의 다른 검사
  `test_extract_usage_metadata_returns_empty_when_usage_is_none` 은 중복으로 보였으나
  남겼다. 통합 검사 쪽은 `usage_metadata=None` 을 첫 청크에 두었는데, None 처리가 깨지면
  그 자리에서 값이 전부 0 인 딕셔너리가 나왔다가 두 번째 청크의 유효값에 덮여 통과한다.

  qa-only 실측을 하기 전에 gunicorn 워커를 `kill -HUP` 으로 재기동해야 했다. 워커가
  15:48 에 뜬 것이라 22:27 의 변경을 싣지 않았고, 그대로 돌렸다면 이전 코드를 측정하게
  된다. 실측 결과 세 결함이 모두 확인되었다. 실제 스트리밍 응답이
  `prompt_token_count=1421, candidates_token_count=158, total_token_count=1766` 을
  활동 로그에 남겼고, `data/chatbot_storage.db` 직접 조회로 `/status` 와 `/help` 는
  0건, `/clear` 는 2건이 저장되는 것을 확인했다. 셋째 결함은 프롬프트 내용이라 화면으로
  볼 수 없고 다섯 갈래를 각각 보려면 유료 호출이 다섯 번 필요해 실행하지 않았다.

  qa-only 가 두 건을 새로 발견해 등록했다. `[CHAT-008]`(P1)은 모델을 부르지 않는 슬래시
  명령이 무료 사용량을 차감하는 문제이고 이번 변경과 무관한 기존 동작이다. 다만
  `/status` 와 `/help` 가 이제 기록에도 남지 않게 되어 "차감은 되는데 흔적이 없는" 조합이
  새로 생겼다. `[CHAT-009]`(P2)는 `/clear` 로 시작한 대화의 제목이 `/clear` 로 붙는
  문제이며 이번 변경이 직접 만든 것이다.

  활동 로그의 `token_usage` 키 이름이 과거 항목과 달라 결함으로 의심했으나 아니었다.
  과거 476건은 전부 사용자 메시지가 `테스트 메시지` 이고 값이 `(12, 8)` 로 고정된 테스트
  스텁이며, 그 키 이름을 읽는 코드가 저장소에 없다. 실제 트래픽이 사용량을 남긴 것은
  이번이 처음이다.
