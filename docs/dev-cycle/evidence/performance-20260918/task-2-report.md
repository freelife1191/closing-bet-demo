# Task 2 누적성과 UI 보고

- 변경 파일: `frontend/src/app/dashboard/kr/cumulative/CumulativeClientPage.tsx`, `frontend/src/app/dashboard/kr/cumulative/CumulativeClientPage.regression-performance-batch.test.tsx`.
- API 계약: `roiByGrade`에 D를 추가하고, `recentWinRate: number | null`, `recentClosedCount: number`, `consecutiveLosses: number`을 화면 상태에 반영했다. 이전 서버 응답에 최근 필드가 없으면 `null/0/0`으로 정규화한다.
- 화면: D 행을 제거하지 않고 D 카드·필터·등급별 상세값에 포함했다. D 카드는 과거 기록이며 신규 매수 추천이 아니라는 라벨과 안내를 보인다. 카드 그리드는 모바일 1열, 좁은 화면 2열, 넓은 화면 4열로 배치한다.
- KPI 원천: 메인 평균·누적 수익률은 등급별 재합산 없이 서버의 `kpi.avgRoi`와 `kpi.totalRoi`를 직접 표시한다. 등급별 상세 수익률만 기존 소수 첫째 자리 표시를 유지한다. 총·평균 ROI는 청산 수익률과 미청산 OPEN의 현재 평가수익률을 단순 집계한 값이며 포트폴리오 복리 수익률이 아님을 툴팁에 명시했다.
- 최근 성과: 현재 페이지 표 행을 계산에 쓰지 않고 서버 KPI만 사용한다. 추천일순 청산 거래 기준 실제 표본 수를 라벨에 표시하며, 종료 거래가 없으면 `최근 청산 0건 승률 (추천일순)`·`집계 전`·중립색·`종료된 거래가 없어 추세를 집계하지 않았습니다.`를 보인다.
- 요청 경합: effect cleanup 플래그로 취소된 요청의 데이터·오류 로그·loading 상태 갱신을 막는다. StrictMode의 초기 effect 재실행에서 첫 요청이 늦게 끝나도 최신 페이지 표·KPI를 덮지 않는 회귀를 둔다.
- 표시 범위: 결과·등급 필터가 `현재 페이지 내` 행만 대상으로 함을 명시하고, 필터 선택이 현재 페이지를 1페이지로 되돌리거나 새 요청을 만들지 않게 했다. 페이지당 개수 변경의 1페이지 리셋은 유지한다. D 등급 상세 네 줄로 높아지는 평균·누적 ROI 카드 두 곳만 `h-auto min-h-24`로 늘릴 수 있게 했다.
- 회귀: 24건/네 등급/서버 평균 2.04%·누적 49%, D 카드·필터, 페이지 전환 뒤에도 30%·7회가 유지되는지, 최근 필드 null 상태와 소표본 2건/50%를 고정했다. KPI 카드·D 카드·최근 지표의 바로 다음 값 노드로 선택자를 한정해 제목·동일 수치 중복을 피한다.
