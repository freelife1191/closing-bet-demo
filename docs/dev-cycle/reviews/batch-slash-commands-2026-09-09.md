# CHAT-008·009 묶음 완료

슬래시 명령의 무료 사용량 차감과 명령어로 고정되던 대화 제목을 고쳤다. 실제 브라우저 검수에서 발견한 사용량 조회 헤더·갱신 이벤트 누락도 같은 흐름에서 보완했다.

## 변경

- 파일 없는 정확한 `/...` 명령은 쿼터 한도 검사와 차감에서 제외한다. 세션·서버 설정 검사는 유지하며, 앞 공백이나 첨부파일이 있으면 기존 모델 경로로 처리한다. multipart 분류와 본문 파서는 같은 규칙을 사용한다.
- 새 세션의 빈 제목을 미설정 상태로 저장하고 첫 비슬래시 질문으로 제목을 확정한다. 화면에만 기본 문구를 표시해 첫 질문이 `새로운 대화`여도 50개 메시지 절단과 재시작 뒤 제목을 보존한다.
- Sidebar는 공용 세션 헤더로 사용량을 조회하고, 전용 챗봇은 응답 종료 후 기존 갱신 이벤트를 발행한다.
- 기존 명령 기록과 이미 정해진 제목은 보존한다. 과거 `/clear` 제목의 일괄 교정이나 저장소 스키마 변경은 하지 않았다.

## 검증과 리뷰

- pytest **2296 통과 / 3 skip**, Vitest **461 통과 / 67파일**, lint **0오류 / 194기존경고**, 타입 검사 통과.
- 실제 빌드·필수 라우트·타입 검증 **3/3 통과**. Python AST 검사는 통과했지만 실제 Python LSP 진단은 사용할 수 없었다.
- UltraQA **App 대응 3회, 필수 5/5 통과**. agent-browser로 실제 앱을 조작해 명령 후10회 유지, 질문2회 후8회, 한도 소진 후0회와 일반 질문 거부를 확인했다. 서버값·저장 제목·스크린샷·요청 상태도 대조했다.
- ponytail SHIP, 코드 리뷰 APPROVE. 아키텍처는 비차단 WATCH이며 종합 리뷰는 COMMENT다. 명령 문법 변경 시 HTTP 사전 판정과 코어를 함께 검토해야 한다.
- 중간에 발견한 multipart 대소문자 불일치, 제목 기본값 충돌, 익명 조회 헤더·갱신 이벤트 누락을 재현한 뒤 수정했다. 실패 원문은 보존했다.

## 범위와 결과

사용자가 제시된 두 항목 설계에 `승인`한 범위다. 코드·테스트 총 **+284 -11 (순 +273)**이며, 실행 코드만 보면 **+33 -11 (순 +22)**다. 불필요해진 메시지 스캔과 그 전용 중복 테스트를 제거했다.

커밋: `63ec882`, `338aae3`, `3e21127`. TODO **48 → 46**. 새로 추가하거나 보류 상태를 완료로 바꾼 항목은 없다.

검증은 외부 모델을 대역으로 바꾼 격리 앱에서 수행했다. 실제 외부 LLM·로그인·과금 서비스의 검증을 주장하지 않는다. 브라우저·서버·임시 사본 정리를 완료했으며 사용자 package.json과 원본 데이터 파일목록은 유지됐다.
