# 개발 라운드 설계와 Codex UltraQA 연결

2026-09-06 대화에서 제시한 설계를 사용자가 「진행해」로 승인했다.
기존 `.claude/skills/dev-cycle/` 정본과 `.claude/agents/dev-workflow.md`를 유지한다.
새 플러그인 패키지나 별도 워크플로 엔진을 만들지 않는다.

## 실행 계약

라운드는 새로운 TODO 항목 하나의 개발 사이클이다. 새 라운드는
`superpowers:brainstorming`으로 분류·설계·승인한 뒤 구현한다. architectural 경로의
설계 문서 검토도 그 스킬을 따른다. 이미 승인한 동일 범위를 이어가는 재개나 QA 재시도는
새 라운드가 아니며 승인과 설계를 반복하지 않는다. `status`와 카테고리 감사는 개발
라운드를 시작하지 않는다.

준비 단계는 NEW, DESIGN_PENDING, RESUME, QA_RUN, QA_RETRY, DONE을 먼저 구분한다.
승인 기록은 시각·범위·대화 근거를 보존하되 파일의 승인 주장 자체를 권한으로 믿지 않는다.
재개는 실제 승인 근거와 해당 항목의 파일 변경을 대조한다. 출처가 불분명하거나 다른
작업의 변경은 보존하고, 자동 스테이징이나 스태시로 치우지 않는다.

QA의 공통 의미는 시나리오 확정과 실행이다. Claude Code는 기존 qa-only/qa를 쓰고,
Codex는 두 단계 모두 UltraQA의 행렬 계획과 실행·진단·수정·정리 절차를 쓴다.
필수 시나리오가 실패·차단·미실행이면 TODO를 유지하고 완료 아카이브를 만들지 않는다.
범위 밖 발견만 별도 항목으로 이월한다. 과거 QA·아카이브 기록은 소급 변경하지 않는다.

UltraQA는 최대 5회, 같은 실패 3회에서 멈춘다. 종료 코드와 실제 결과·증거·정리가 모두
통과해야 COMPLETE다. App에서 OMX 쓰기 범위를 확정하지 못하면 hook 소유 상태를
고치거나 세션 ID를 만들어 넣지 않는다. QA 문서의 실행 메타데이터로 App 대응 절차를
수행하고 native lifecycle 미사용을 기록한다. 정상 OMX 문맥은 CLI 상태 관리를 사용한다.

감사 에이전트는 코드·문서·TODO·런타임 상태를 모두 읽기 전용으로 두고 보고서와 항목
초안만 반환한다. 결과를 저장하는 주체는 호출한 리더다.

## 검증

정적 검사만으로 완료하지 않는다. 실제 Codex 스킬과 전용 역할을 새 임시 실행 문맥에서
호출해 상태 조회, 신규 설계 승인 전 쓰기 차단, 승인 후 정상 완료, 재개, 필수 QA 실패,
거짓 성공 출력, 악성 입력·주입, 감사의 읽기 전용을 검증한다. 시간 초과·반복 실패·정리는
한정된 로컬 하네스로 실행한다. 실제 금융 앱·시크릿·운영 데이터에는 연결하지 않는다.

평가자가 출력 문구와 별개로 Git diff·커밋·TODO·아카이브·종료 코드를 판정한다.
도구나 하네스 설정 실패와 워크플로 실패를 구분하고, 필요한 재실행만 수행한다.
임시 프로세스와 fixture는 정리하고 실행 요청·결과·판정은 검증 보고서에 남긴다.
